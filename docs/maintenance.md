# 资料维护约定

版本流水统一记录在 [CHANGELOG.md](../CHANGELOG.md)，按版本整合同一改动，不按来源重复记录，也不附来源标注；独有的机制细节和验证边界合并保留。总README只保留项目介绍和入口；发行说明写当前用法，实现说明写当前源码位置，构建说明写可执行流程。不要向这些说明页追加每次版本的变更段落。

研究文档按主题保存原生行为、调查证据、适用版本和验证边界；它们可以注明历史背景，但不复制整份变更流水。中文能力文案只在 `docs/hexes.md` 维护，英文只在 `docs/hexes.en.md` 维护，附加效果的中英文状态文案只在 `data/text/status-effects.json` 维护。按编号关联，不在代码中另外保留翻译副本，不自动覆盖用户编辑的任一语言。

## 今后的规则

1. 新调查暂存 `.work/<主题>/`；结论确定后更新对应主题文档，保留能复现的最小探针或检查。
2. 不再用版本号目录作为构建输入。版本只标注适用范围／验证记录，稳定输入用描述性的路径。
3. `dist` 只保留当前包及当前机制检查；不把所有历史 scope JSON、启动日志或源码快照混在发行包里。
4. 原生绑定依据 EXE 哈希、唯一特征、caller 与 ABI；旧采样可以帮助定位，不能当作当前版本证据。
5. 用户反馈写明实际验证的机制与场景。静态、隔离测试、加载和联机玩法不互相替代。
6. 用户配置持续保留，生成表可重建。清理 `.work`、`target` 和 C# 的 `bin/obj` 不应影响源码和固定输入。

已有清理记录见 `cleanup-report.json`。构建的输出和测试记录放 `.work`，用完可删。

缓存清理使用 `./clean.ps1 -CachesOnly -Apply`；不带 `-Apply` 仅预览，不遍历目录联接或符号链接的目标。
