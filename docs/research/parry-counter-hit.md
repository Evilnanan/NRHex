# 交锋：防御反击再次招架计作回复命中

适用版本：0.17.270；EXE SHA256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`。

交锋成功招架后，带着 COUNTER 增益的防御反击在自身交锋窗口内再次成功招架，也提交原有 RECOVERY 效果：35% 最大血量、65% 最大精力，祈祷一击视觉。这里只扩展交锋自己的回复条件，不伪造对敌伤害或向其他命中特效广播命中。

## 动作识别

旧的所有交锋窗口共用行为标记 95002400，只能证明正在交锋招架，不能识别防御反击。现在每个窗口把 `96000000 + 原条件 stateInfo` 写入 TAE type 0 参数的 +8。原生 `40D443` 保留完整 32 位值至动作模块 +24C，同时设置原 guard 位；持续时间和条件 +0E 不变。运行时把该标记还原成当前包的 CONDITIONS 键，沿原有 PlayerIns vtable +260／+328 解析当前手与实际攻击行为，只接受目标参数中五项 subCategory 任一为 103 的行为。独立版和 MMV 分别生成分类表；不硬编码反击动作号、武器或动画号。

所有原生防御参数查询仍经已有 hook 把私有标记映射为 460。连续招架的临时 guard 借用保留当前有效攻击标记；只有反应动作的继续招架使用旧通用标记，因此不会因上一击留下 COUNTER 而误判为正在反击。新逻辑要求本次通知前已有 COUNTER；没有先前交锋的普通防御反击只在首次交锋时提供机会，不当场回复。

## 回复机会

保持现有“每次成功交锋提供一个、不叠加的回复机会”规则。再次招架属于上述反击时，先提供机会，再经 APPLY_SELF 提交 RECOVERY。共享效果 hook 的 recover_once 同步移除 RECOVERY_READY 后才提交回复，因此随后的多目标、多段和重入共用已消费的机会。原生拒绝提交时仍保留机会。

这不是按动画编号限制每个动作一次：已经命中过、随后又成功交锋，仍是新的机会；同一动作中的另一次有效招架也仍会提供机会。普通攻击招架、反应动作连续招架和手动防御不新增直接回复。

## 验证范围

运行时夹具覆盖：有／无先前交锋、真实反击／普通行为分类、再招架消费、后续多目标拒绝、无效通知、嵌套 guard 恢复、拒绝提交与重入。两份资源增量修改只允许每个私有 guard 的四字节 judge；重新读取 binder 和 TAE 校验，保留原时长、条件及其他字节。完整生成器也输出同样的标记与分类表。

`tools/verify_parry_counter_hit_native.py` 隔离执行原生 TAE 写入片段和 APPLY_SELF 包装；下层分派用桩函数，同时核对普通分派到共享效果入口的调用位置。这不等于游戏中或联机验收。游戏内仍需验证不同武器反击再次招架、MMV 专属反击，以及客户端／主机。
