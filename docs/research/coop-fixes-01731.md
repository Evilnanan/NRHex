# 0.17.31 刷怪笼副本生成、战技显示与嘉豪身法

用户最新双人原生联机经私服测试：刷怪笼只有房主能看到 BOSS；百般武艺的队友武器仍显示原战技，先预测旧动作，再被同步动作纠正。另要求嘉豪的后跃命中只对非失衡敌人回复绝招，并更名为嘉豪身法。上轮单人黑雾与图标排序暂未再报告异常，但不能据此认定联机生成成功。

## 刷怪笼

0.17.27 把抽选、生成、结算一起放到房主分支。Battle 在所有端先隐藏并卸载克隆单位，远端随后被 HostOnly 结束；Birth 仅恢复 backread，再等待模型加载和 HP 大于零。队友没有执行生成器，事件可以一直停在等待副本。

当前原生 common_func 的 90065031 在关闭事件同步后执行 2003[54] InvokeEnemyGenerator，没有 OtherWorld 结束守卫。新版本保留房主选怪、AI 网络控制权、难度与红化决定、死亡和奖励结算，把对应生成器调用移至每端 Birth 的恢复 backread 后。各端采用同一个已提交的 choice，使用对应固定地图单位的生成器；不会由队友重新抽选。四份当前 MSB 的 84 个生成器逐项回读：GenType=3、InitialSpawnCount=0、LimitNum=-1、MaxNum/MinGenNum/MaxGenNum=1，每个只绑定一只对应单位。

现有 0.17.29 新出场／进行中分支、黑雾、动作、血条、7999 联机激活标记保持原样。进行中重连先检查该成员的共享死亡位，已死成员不重新生成。单体也增加对应死亡位：新单位活着后清除，死亡判定成立后设置；只在进行中分支读取，避免上次死亡位挡住下一次新出场。复数组沿用既有成员死亡位；非战斗坐骑不套用战斗成员死亡位。

增量包修改四份地图的 200 个 Battle、336 个 Birth。构造器、HUD、抽选、组死亡事件、common、MSB、regulation 和其他事件不变。每个生成器一次最多一只、每端执行原生流程是静态依据；原生联机网络所有权仍须实际双人验收，事件模拟没有模拟真实网络生成器。

## 百般武艺

原本仅在本地战技 getter 和行为查询中返回按实例重铸的结果。原生 6C16F0 导出的武器记录仍读取 6A1DF0 原始 +1C override，队友因此拿到旧战技。

沿用现有 6C16F0 挂钩，增加一个保持原始两参数和返回值的包装入口，从调用栈获取发送来源。只允许已核对的五个原生导出调用返回地址：381602、38177D、20CB11、B0E0D3、BEA18B。前两处为完整／备用装备快照；20CB11 位于 PlayerGameData 导出 20CA00（NetChrSetSync 4E58A0→66E3A0 调用）；另外两处为公开角色装备及队友装备信息导出。五处直接调用指令纳入版本特征检查，不能只凭过去地址命中。

输出必须属于本地持有者的六个实际装备句柄之一，并匹配缓存中的同一代实例及基础武器 ID。仅修改临时 0x48 字节输出的 +4 战技 ID，其他字段保留。丢弃／替换拾取的线程作用域优先排除；库存预览、事件物品创建、原生比较及其他来源保留原值，实际库存和武器实例不改。弓使用独立战技池；风暴管束者及原始小圆盾格挡保护规则、架势重铸时机不变。

原生快照接收／复制 382E30 用 6C11F0→6C0C70 比较记录，即使武器基础 ID 相同，也比较 +4 override；6A0100→6A08B0 创建的实例恢复该值至 +1C，原生战技查询可读到新 ID。接入的是原生发送快照，未增加自己的网络报文或写入存档的战技修改。实际报文到达和队友动作仍待联机测试；隔离比较验证仅覆盖基础 ID／战技不同的早返回分支，不冒充完整装备同步实测。

## 嘉豪身法

名称更新为嘉豪身法，中文描述采用用户最新 Markdown 的“后跃攻击进行反击”文案；实际命中回复仍明确要求非失衡。原生 SpEffectParam 50／51 的 stateInfo 为 434（韧性失衡／防御击破）；用已有 508E20 原生状态查询检测有效条目，同时排除短暂的 36 开放处决窗口。不会使用普通受击动作或削韧触发请求位作为持续失衡判断。

已失衡目标不排队回复，也不消耗此次后跃的回复机会；同一后跃之后命中正常目标仍可回复一次 25%。近战／远程过滤、整次动作去重、量表增伤、正面处决 25% 回复、翻滚损失改为30%，受损扣除仍为30%。中英文名称与三份说明增量更新，用户 Markdown 的其他文案保留。
