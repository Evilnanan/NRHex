# 结晶外壳弹刀模块与崩溃调查

## 现场证据

2026-10-12 20:44:01，项目dist的0.17.64在挨打时崩溃。用户持有结晶外壳、百般武艺，补充本次与上次均发生在被多名敌人围攻时。转储模块路径确认加载的是`dist/mod/natives/NRHex.dll`。记录副本保存在`.work/crystal-crash-01764`。

异常为访问冲突，游戏RVA `3F6BD3`的`mov rbx,[rdi]`读取非规范指针`3E800000C7A035D0`。该处属于HKS动作2027，调用者`407FF0`从角色行为模块取动作脚本上下文。指针高32位`3E800000`恰为浮点数0.25。有限转储未包含相关堆对象，无法重建先前写入者；不能把栈扫描所得地址当作完整调用栈，也不能据此证明全部历史崩溃都源于同一错误。

## 验证及限制

`tools/verify_crystal_rebound.py`直接核对当前EXE取模块指令、RTTI和对象大小，并在独立映像内执行原生比较与弹刀选择。旧错误以分配足够空间的受控缓冲区模拟：设置攻击强度60、防御强度70后，真实原生函数在越界的`+74`处写入0.25，说明其可产生与本次指针损坏高位一致的数据。此验证不证明现场相邻对象的具体排列；但错误模块及越界写入本身已经确定。

Rust回归用相同所属角色的命中停顿对象作为干扰项，确认正确槽位被选中，并拒绝错误类型、空槽位、错误所属角色和非直接来源。原有连续命中只抵挡一次、冷却、命中副本与原生调用约定检查继续通过。共214项Rust测试、32项原生强度比较和30项原生弹刀场景通过。

围攻情况下会有更多命中和动作处理，用户线索与此错误可同时成立，但目前没有证据证明另有并发竞态。此次未运行游戏，仍需实机验证连续破盾、被围攻以及与百般武艺同时持有时的稳定性。
