# 联机与新海克斯复查（0.17.34）

后续更正：0.17.36 的现场测试证实死亡后的效果发射被跳过，并纠正了灵魂描述符的字段解释。当前实现以 [现场诊断](new-hexes-live-fix-01736.md) 为准；下文保留当时记录。

本次修正刷怪笼的本地事件生命周期，以及气球／强化【召唤灵魂】的倒地状态判断。没有运行游戏、联网或修改游戏进程。百般武艺的原有同步补丁保留；自爆在濒死状态下实际命中敌人，以及重铸后第一次出手前的数据送达，仍不能用离线检查宣称已解决。

## 原生生成与刷怪笼

核对原生 common_func 的 90065910、90065000/1、90065031、90015022，以及当前 EXE 的 Generator 实现。塔楼出场事件操作地图中预先定义的敌人，按共享旗标启用；模型、黑雾、动作和血条各有本地执行部分。90065031 使用本地事件调用生成器，不能仅凭这一点推断全部网络权限。

进一步核对的 Generator 构造入口为 4DC7F0，状态表 398CA60。4DF850 从 MSB 的 SpawnPart 索引解析现有地图角色，4DE5E0 选择可复用角色，调用角色虚表 +5A0 重置。基础角色实现 3D57B0 恢复生命、模块和世界加载状态。因此这里的生成器绑定既定地图角色身份，不是每端任意分配一只新 NPC。刷怪笼现有每角色单生成器、MaxNum=1、单 SpawnPart 保持；选择、红化抽取和结算保持房主权限。

发现并修正三个具体问题：

1. Battle 在检查房主身份之前关闭模型加载，而 Birth 会恢复加载。重新载入或晚加入时，两段事件可能先恢复再关闭，队友端 Battle 随后结束，不再自行恢复。准备阶段的隐藏、停 AI、卸载统一移至本地 Birth，Battle 先检查房主身份。
2. Birth 原来把模型卸载也当作本轮结束，导致同一个选择旗标仍有效时再次调用生成器。现在本地生命周期由该轮选择旗标控制，流式卸载不请求重新生成。
3. 模型就绪和正 HP 的等待原来不可取消。队友错过整场战斗时可能永久等待已结束的敌人。新开与重连两个等待分支现在均在该轮结束时取消。

正常结束后保留与房主尸体清理一致的等待，避免下一次准备提前隐藏尸体。复数敌人的已死成员重连分支仍不生成。四张地图共修改 336 个 Birth 和 200 个 Battle；奖励、血量修正、登场特效与动作指令，以及其他事件和构造器不变。完整构建的生成逻辑也已同步修改。

模拟覆盖 2,328 种延迟、卸载、再次开启、取消加载和已死成员重连情形。它验证事件控制流，不模拟网络包、游戏的条件锁存全部细节或真实生成器；仍需双机验收。不能据此断言此前两球／两只 BOSS 或血量偏低的全部原因已排除。

## 气球与原生救援

原有判断使用 HP 和 102100。102100 持续时间为零，只适合作为触发信号，无法覆盖完整倒地过程。进一步追踪原生 66F3B0、674EB0、66D700 后，改为读取 Player +710：0 正常、1 濒死、2 复苏过渡，并保留 HP 为零的死亡判断。102120 虽然是长效，但原生还用它保护濒死计时，不能代替角色状态。增加 66D700 的唯一签名检查；整份 EXE 的既有 SHA256 门禁保持。

该判断同时用于气球倒地去重和灵魂保留。正 HP、效果暂时清理、濒死到复苏过渡均不能重新触发同一次气球，也不能丢掉已经储存的灵魂或允许倒地召唤。

原生 43D260 对濒死玩家另行调用 66DEC0，计算救援值并更新救援计量、救援者与网络通知。因此救援有独立结算分支，不能把观察到的差异全部归因于阵营。当前自爆仍沿用独立黄金冲击波弹体和最大 HP 伤害写入，禁止自己／友方命中；没有改玩家阵营、濒死状态或救援逻辑。

**未解决的验证缺口：** 允许给死亡者添加发射效果，不等于证明死亡／濒死来源的弹体能通过原生碰撞和目标筛选。现有伤害覆写在计算后执行，无法救回更早被过滤掉的命中。本次没有找到足以安全限定到气球弹体的原生过滤修正入口，没有添加全局攻击放行。验收必须看敌人实际 HP 和冲击，不能只看黄金特效或飘字；同时确认队友正常救援、不被自爆伤害。

## 百般武艺

复核现有五处原生装备序列化出口和接收端 382E30 → 6C11F0 → 6C0C70。临时记录中的战技 ID 能进入队友实例；接收端在武器基础 ID 相同、战技 ID 不同时也会重建数据。掉落／拾取排除仍保留，不直接修改共享武器参数。

本次还追踪 4E58A0 的网络状态打包、66E3A0 → 20CA00 的完整装备载荷、20C8D0 的另一载荷分支，以及 675D20 的更新路径。完整装备载荷每次调用都遍历六个武器，但它不是所有角色状态包都必经的路径。另一个 4F2000 → 4F3B80 通知主要携带装备选择索引，不能当作强制发送完整新战技的方法。

因此本次没有依据不充分地添加脏标记或手工发包，也没有修改此模块。上一版补丁修正的是“序列化时输出什么”；何时触发对应完整载荷，以及首次动作前的时序，仍需确认。验收应连续重铸后立即再次出手，并交换房主和队友身份。

## 强化【召唤灵魂】

复核团队归属句柄、仅保存整数描述、最后击杀覆盖、私有 NPC 禁止奖励／再次捕获、空家人槽召回、单个自定义灵魂，以及原生创建和 1B 网络载荷。3918D0 在返回成功句柄前已经建立角色实例，资源加载后的友方／白灵初始化由 392810 继续处理；没有用尸体指针延迟召唤，也没有接管正常家人槽。本次除了倒地状态判断，未发现有充分证据需要调整的创建协议问题。

仍待验收不同 BOSS 模型的 AI、白灵外观、每秒扣 1/15 最大 HP、实际持续时间、双方可见和团队击杀记录。48 字节载荷及模拟 ABI 正确不代表实际联机通过。
