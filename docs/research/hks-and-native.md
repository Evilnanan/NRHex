# 动作脚本与原生运行时

用于 HKS/TAE、输入、空间量、native API 与 Rust hook。方法可复用，函数 ID、成员偏移、地址和机器码仅对已核对的游戏版本成立。

## HKS 使用原始字节码

编译 HKS 的反编译输出是调查材料，不保证可重新编译为等价脚本。大型复合表、寄存器重用、闭包、SETLIST 和伪代码可能通过语法检查却改变脚步、动画或状态机。小改动优先保留原始二进制并修补目标函数，不将整份反编译稿作为覆盖交付。

字节码补丁须确认原始文件哈希、目标函数身份/指令序列，并处理实际格式：

- 指令、常量、调试行、局部变量范围和后续原型对齐一起更新。
- 部分全局读取使用旁边的缓存槽；追加常量保持这些槽和 nil/padding 的布局，不能只拼字符串。
- 检查可用寄存器数与参数/中途活跃局部变量。入口可用的临时寄存器不代表函数中途也可用。
- 中途插入时重新定位跨越插入点的分支，并明确跳到边界的分支是否应执行新代码。前缀插入也会影响局部变量/调试范围。
- 追加控制流保留原生死亡、无效状态、动作取消与体力等守卫，只对目标拥有者生效。

当前读取的 HKS 数值常量按 f32 存储，大整数 ID 会舍入。不能把仅供 native int 使用的 ID 原样传进 HKS。通用检查：

```python
import struct
assert struct.unpack('>f', struct.pack('>f', effect_id))[0] == effect_id
```

超过 `2**24` 后整数不再逐个精确表示；所需步长随量级增长。在约九千万的编号段步长为 8，但不能把“所有 ID 都选 8 的倍数”当跨量级规则。HKS 需要的拥有者/脉冲可用独立的精确 ID，再由 native 关联实际效果。

验证补丁至少包括：修改/未修改分支的控制流执行、活跃寄存器保留、序列化后重新解析、精确反向还原源文件，以及独立反编译后只出现预期语义变化。其他原型保留原字节；不以“反编译器没报错”代替这些检查。多个补丁按固定顺序从已核对输入组合，并核对每阶段的输入/输出关系。

## 动作、输入与状态通知

HKS 的 `env/act` 数字是脚本分发编号，不是 EXE 地址。查当前脚本和 dispatcher，确认模块、参数宽度、调用对象与单位，再定位其实际 API。动作名称与参数行别名只是线索。

功能失败时检查多个控制层：全局许可变量、动作回调调用点、TAE 输入许可、原始请求/过滤请求、接触/落地条件以及动画阶段。一处许可变量改成功，不表示后面的输入屏蔽也已解除。

TAE 事件可能按时间窗口关闭跳跃/翻滚等输入，或只在真正起跳后的阶段添加效果标记。只读比对原始 TAE，采样原始按键与过滤结果可区分“没有按下”与“动画吞了输入”。若只需允许特定情况下一个原请求，可在原 getter 返回拒绝后，凭本地拥有、存活、贴墙/空中、对应动作阶段等条件放行；其他参数和原结果保持。无需为此全局放开输入或覆盖整份动画。

异常状态存在、HP/FP 已变化、原生受击通知和动画请求是不同信号。已核对的发狂动作分支读取“本次伤害的异常属性”，而不只看持有效果状态。直接施加自异常 SpEffect 可能累积/触发状态，却没有动作所需的通知。遇到这种情况先跟踪原生伤害通知与 HKS 分支，必要时以限定拥有者、自动过期且消费一次的标记连接原生动作事件，保留原动作保护。连接代码构建通过不等于动作已经实测成功。

需要咏唱期保护时，可在实际施法启动/循环/发射回调发出短心跳，由 native 管理临时效果。区分上半身动作、恢复/取消、战技施法与普通法术；按键按下不能代替正在咏唱。当前施法 ID 应取原生动作模块的 getter，而非上次命中的法术，慢弹体和切法术会让后者过时。

## 空间、下落与手持对象

优先沿原生 getter 找坐标/高度；位于附近的向量可能是碰撞上下界、历史位置或落地参考点，不能靠偏移相近猜。区分当前帧与上一帧的 grounded 标志，落地边界会影响是否清空记录。

脚本接口可能把原生米乘 100 转成厘米。比较距离、跳跃高度或射程前核对 dispatcher 的转换，参数配置值也未必是实时测量值。

已核对的原生下落高度以落地参考位置与当前 Y 相减；特殊高跳上升到参考点以上时可为负，普通落地又会重置。灵魂气流的区域配置高度是起跳资格/预设，不是这次飞行的下降距离。

地图图标线索可沿 `WorldMapPointIconParam → WorldMapPointParam → MSB region/part → 地图 EMEVD → HKS` 追到起跳条件。地图还可能用普通/可封印区域或“伪气流”效果开启高跳；外观相似不代表同一 region 类型。大地图的分块与复合地图分别检查，未在一个文件找到不表示机制不存在。

需让特殊高跳计入高度时，在地面记录起跳资格，离开区域后的首个空中帧仍能识别，随后跟踪该次飞行的实际最高 Y。仅对确认的特殊起跳使用跟踪值补足原生高度；普通跳跃继续遵循原生参考，不能把所有上升都转换成下降收益。落地宽限只从第一次落地计时，后续命中/地面采样不得续期；多段是否共用首段高度按设计决定。

“已装备”和“正在手持”也不同。核对原生手持 getter 如何选择当前槽位，以及双手握持是否将另一手映射到活动武器。不要把背上的武器、所有库存武器或非唯一的特殊攻击类别当手持依据。原生 getter 还可能通过指针输出/返回引用，不能假定返回寄存器直接就是武器或法术 ID。

## 原生函数与 hook

基于本版本 PE 区分文件偏移、RVA 与加载 VA；沿调用者、dispatcher、虚表和数据读取者建立签名证据。旧 CT 可作定位线索，不直接调用历史地址。`.pdata` 不覆盖所有叶函数，查询不到时不能把相邻函数的 unwind 区间当目标边界。

Windows x64 ABI 要从真实调用点确认：整数寄存器、XMM 参数、第五项起的栈参数、byte/int/pointer 宽度、返回 AL/RAX/XMM0、指针输出、对象模块与 vtable 槽。返回 byte 不天然意味着成功布尔；保留全部原参数及原返回位宽。

Rust 可用 `cdylib` 由 ME3 加载，初始化离开 loader lock。原生游戏 API 按已验证的游戏线程入口调用，后台线程用于初始化/诊断而不是任意生成奖励、施法或改效果。

hook 引擎需完整指令边界、RIP 相对访问及直接分支重定位、跳回地址和跳转距离处理；不能按固定字节数截断指令。安装时先准备所有 trampoline/状态，再在受控写入窗口修改代码、恢复页保护并刷新指令缓存。部分安装失败时不得将未就绪功能标成 ACTIVE。

中途 hook 还有原函数的活跃状态：保存 RFLAGS、易失整数寄存器/XMM、按该位置真实 RSP 对齐留 shadow space，再重执行覆盖指令；围绕原函数的回调还要保留它的整数/浮点返回。异常或 panic 不得穿过原生 ABI。

由纯状态机计算动作，再在锁外调用原生增删效果，可避免 native 回调重入导致死锁。命中 callback 尽量只做当前命中的原子决定和排队，效果链表操作在安全 Update 时机处理。使用原生删除 API，而非自己改链表指针或释放节点。

临时描述符改动用同步调用范围/TLS 限定；考虑同对象重入、不同对象嵌套以及 A→B→A，不能用一个全局布尔或“上次命中指针”就认为已经去重。另一类需要流入网络副本的命中修改应保留其生命周期，见 [效果与战斗结算](effects-and-combat.md)。

## 延迟、叠层与诊断

原生效果应用可能排队，到角色后续更新才进入有效效果查询。创建节点、加入效果列表、更新数值和显示可分阶段完成。依实际操作选完成信号：奖励用实际节点创建；充能用量表回读并跨帧确认；事件握手用提交后的确认标记。短时本地门控保护尚未可见的原生冷却/领取记录。

同一动作可能连续几帧发送相同效果标记，消费可能先于通知发生。保存必要的前态，并以实测时间/动作身份合并重复通知；普通 CD 只能给近似语义，不能宣称精确识别一次施法或一次命中。

同 ID 重施可能刷新或替换，不应默认独立叠加。需要每层独立到期时可用不同 ID 的有限效果池，加本地到期记录并只复用已结束槽；聚合层数统一刷新的设计则用另一套计时。容量按合理最大触发率与时长确定，不凭空添加隐藏玩法上限。死亡、失去拥有、对象/stats 转换分别清理临时状态，持久资格交给原生记录。

保留单位明确的游戏时间与墙钟时间。周期回血/耗蓝等通常沿 Update 的游戏帧时间；处理非有限/异常 dt、保留小数余量，补算多个脉冲前重新确认资源，避免用旧 HP/FP 快照透支。短过渡超时/采样窗口可用单调墙钟，不能未经确认就把暂停菜单的墙钟消逝当游戏冷却。

诊断围绕待证的最小问题做限时/有界记录；只读观察也需检查 PID、DLL 版本、结构布局和指针有效期。优先早期退出非本地/非目标路径，避免每命中分配容器、遍历整条效果链、同步开文件或向调试器镜像。

已验证功能清理诊断时，保留实际握手、状态心跳、前态保存和跨帧确认；这些不是日志。移除诊断源码、计数器、纯诊断 HKS 脉冲及参数行应作为有范围的改动验证。日志频率下降和用户卡顿改善不能直接证明具体帧时间收益。

隔离执行当前 EXE 的小函数时，核对机器码、外部调用、RIP 数据、跳转表及需要的重定位，用合成对象/受控桩函数，不将随意映射整个 PE 当作可安全运行整套游戏。记录哪些依赖被替换；证明仅覆盖实际执行的谓词、ABI 或倍率路径，不扩展成游戏/联机验收。
