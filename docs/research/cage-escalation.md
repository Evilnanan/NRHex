# 刷怪笼重复开启与层数

当前规则：拥有者可以无限次重复开启监牢，不再有 5 次的开启限制。首次自定义开启不强化；之后每次增加一层，每层攻击倍率 1.1、受到伤害倍率 0.9，均由原生 SpEffect 逐实例乘算。次数按本局内的玩家和具体监牢实例分别保存；一次共享遭遇使用本次开启者此前的次数。普通钥匙流程不消费此计数。

`CageEscalation` 是最终资源生成阶段，放在独立版完整生成之后、MMV 新遭遇追加之后。它保留按需创建、奖励、骑乘、音乐及战斗主体。MMV 事件合并前会撤销独立版的这一层补丁，合并结束后按最终的 109 个遭遇重新分配标志并生成。四张监牢都覆盖；MMV 原包不改。

## 状态与联机

- 原有 category 5 私有计数起点保留，扩展为 32 位。达到整数存储极限也不阻止开启；这是存储范围，不再作为次数门槛。
- 每次开启在发请求前，把旧计数逐位发布到新分配的 category 7 共享标志，再自增个人计数。每位只写一次 ON 或 OFF，避免原生网络编码先 ON 后 OFF 导致 clear-then-set 失效。
- 共享标志和每端本地应用进度通过完整事件参数、事件 ID、批量清理／随机范围扫描避让。选择器和 MMV 的现有标志不改。
- 每端等所有本组角色完成生成、启用和原生联机修正后，清除残留强化，再按发布层数添加本地效果。原生按 ID 移除可能只移除一个节点，因此逐帧排空后才重建。
- 出生流程在显示完成前清除本端应用状态；重载地图不以旧进度跳过，也不在旧层上继续叠加。房主在应用完成后才启用 AI。
- 保留原来的 busy/request 防重复开启机制。并发开启和网络重连的真实时序仍需联机实测；离线事件模拟不等于联机验收。

## 参数与 HUD

`95001604` 从中性标记生成，`spCategory=10` 允许同 ID 的多个独立实例，`stateInfo=0` 不参与状态互斥，`effectEndurance=-1`，`isDisableNetSync=1`，由各端自己的事件重建。只改五种攻击倍率与八种承伤倍率，不改最大血量。`wepParamChange=0` 是不限定武器类别，不能误改成 1；`throwAttackParamChange` 是仅抓取攻击过滤，也不能启用。魔法、祷告及灵魂法术适用位开启。

使用加攻图标 `20406` 与减伤图标 `20408`（原生螃蟹效果的主图标），开启永久效果图标显示，关闭 `dispDartDebuffStacks`。此前把 `20406` 当成组合图标是错误的。

原生小血条使用 `50A890 → 511A00 → 7DEB30` 汇总，但大血条更新 `7D8020` 对群组实体主动清空图标。新增 `cage_hud` 在原更新之后，只为已绑定刷怪笼 NPC、且原生图标列表为空的群组血条补收集有效的 `95001604`。取一名存活成员，避免复数成员的层数相加；通过原生收集器生成两个图标及各自层数。保留原来的群组血量、名称、实体和其他 BOSS 行为。

2026-10-27 现场：首个监牢连续开启的强化正常；之后另一监牢的神兽战士 HP 已为 0，红狼仍存活，二者均有 ready/choice/shown，但没有 spawned 和强化 done。这解释了无大血条、无击杀文字及占用不解除。修正版将新增工作事件从所有地图重复的 `9102xxx` 改为经过占用检查的地图前缀 `85xx–89xx`，临时位从低位 `5000` 改为 `5800` 起的空闲区域，避免跨实例身份和原生隐式状态冲突。故障环节已由只读现场确认；修复因果及跨监牢效果仍需游戏验证，不能将静态检查当作验收。

## 验证与边界

`tools/verify_cage_escalation.py` 对写回的实际事件执行模拟，覆盖持有／未持有、钥匙、房主／客机、超过 5 次、不同位宽值、忙碌／夜晚阻挡、未生成角色、多个成员、重载残留及重复帧。四张独立版共 3644 个案例，MMV 共 5296 个案例。

固定 EXE SHA-256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`。隔离执行原生 `510B20 / 510B70 / 510BD0` 验证不合并／替换同 ID 层；`7DEB30` 验证永久效果的 0、1、2、5、6、10、50、100、255 层汇总；`502830 / 503800` 使用实际生成的 PARAM 验证 0、1、2、5、10、32 层的攻击和减伤乘算，以及五种攻击适用类型。只替代离线测试中不存在的 PARAM 管理器查询，不访问游戏进程。

事件写回验证格式、元数据、参数绑定及内容，并检查撤销新增事件、门控与初始化参数后能逐事件恢复输入。参数只新增／更新一个私有效果；中英文文案移除旧次数限制，不公开隐藏强化机制。测试产物位于 `work/cage-escalation/`。

首次监牢的 0/1/2 层已从现场节点确认。2026-10-27 更新并重启 MMV 测试版后，用户反馈上述修复测试成功；未单独报告双人联机验收。极高层数受浮点和原生 HUD 表示范围约束。
