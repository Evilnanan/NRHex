# 详细状态页归栏修正 0.17.32

用户实测 0.17.31 的能力说明和“可以抵挡一次攻击”是两个独立条目，但都在特殊效果。文本、图标和 Attach 映射审查不能证明 UI 归栏，旧结论撤回。本次仅修正详细状态页路由，沿用上一版文案。

## 当前原生证据

当前 EXE SHA256 为 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`，版本1.3.3.0。

- A89700 添加106103“特殊效果”入口0、106110“附加效果”入口1。A8AC10 的选中条目 `+CC=0` 对应 `+2CB8` 容器；入口1对应 `+22C0`。
- 830EA0 将正在生效的 SpEffect 写为44字节 kind 0 记录，将装备 AttachEffect 写为 kind 1 记录。两者具有不同 payload；直接改 kind 会使参数读取错位。
- A898F0 查询目标角色，由 A89A93 的 `MOVD EAX,XMM2; CMP EAX,1` 决定目的容器：kind 1进入 `+22C0` 的附加效果，kind 0进入 `+2CB8` 的特殊效果。能力所有权效果和护盾就绪效果均是 kind 0，因此同时出现在特殊效果符合原有代码。
- 两个分支均调用8FF2D0创建同一种64字节显示条目。8FFCE0的通用渲染先检查 AttachEffect 指针，再检查 SpEffect 指针；后者沿用 SpEffectText 名称、说明、图标索引和 `+38` 原生计数，不依赖外层容器。两栏都能安全展示未经改型的 SpEffect 条目。
- A5F770 使用保存的角色／装备数据填充局外状态页。新增路由限于查询活动角色的 A898F0；这些临时状态 saveCategory=-1，不添加任何持久拥有记录。

原生的区分通常是生效状态和装备附带词条的来源，不是永久与临时的语义分类。8610702护盾仍是 live SpEffect；仅凭其文本或用户先前的栏位描述，不能推导自定义状态已经进入附加效果。

## 实现

新模块 `src/status_display.rs` 在现有原生分流比较处进行 UI 路由。只允许 kind 0 的下列状态走附加效果分支，保留 EAX=0 和完整源记录：

| ID | 状态 |
| --- | --- |
| 95000701 | 结晶外壳护盾 |
| 95000403 | 终极刷新就绪 |
| 95001203 | 逃跑计划就绪 |
| 95000501、95005001～95005079 | 豪饮80个独立增攻层 |
| 95000801 | 受击隐身 |
| 95001201、95001202 | 逃跑计划生效／冷却，仍按原参数隐藏 |

其他记录执行原MOVD/CMP的重定位代码；装备、原生buff、能力说明和没有图标的隐藏记录不扩充也不改型。R10临时使用后恢复，原始44字节记录、寿命和叠层计数不写入。原生插入、容量扩充和两栏刷新流程继续执行。本次不修改 regulation、事件、HUD 排序或文本。

## 验证范围

167项Rust测试通过。新增测试在私有内存执行当前 EXE 的7字节原分流指令、真实 naked detour 和真实重定位代码，覆盖4种kind和98种ID的392组合：全部自定义层、范围边界、能力ID、原生盾／buff和未知kind；验证目的分支、源记录、EAX类型与R10恢复。运行时新增唯一签名及7字节覆盖长度检查，63项特征定位通过。

构建、文件范围和DLL加载与实际游戏页面测试分别记录。隔离分流测试不等于已打开游戏页面；实际自身／队友页面的归栏、状态消耗后消失和豪饮计数仍待验收。
