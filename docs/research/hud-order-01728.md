# 可用状态图标排序，0.17.28

用户复测反馈：0.17.27 的百般武艺与嘉豪身段修复有效，特殊效果列表已经稳定，但血条旁图标仍会交换位置。这次修复同时覆盖原生 HUD 与列表的独立比较器。未将此前反馈扩大为所有动作或联机场景验证。

## 当前版本证据

目标 EXE 1.3.3.0，SHA256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`。当前 regulation SHA256 `811009668e64eed72159851de962bd83f2bda06542d8c860abcdc11970daafa5`。本次不修改 regulation、事件、地图或 HKS。

本人与队友 HUD 分别经 7DB180／7DA8B0→50A890→511A00 收集当前有效效果。7DEB30 原生聚合生成 20 字节条目：效果 ID、图标 ID、图标索引、剩余时间、数量。7CFE40 在转换 HUD 绘制数据前调用 7DEF90，后者将 7DF110 传给原生排序函数。特殊效果列表走 82BA40，不能用它的修复证明 HUD 已覆盖。

7DF110：同效果 ID 按子图标索引排序；两个负剩余时间的永久效果按图标排序；永久效果先于有限时间效果；有限时间效果按剩余时间降序，再按图标排序。82BA40 另保留原生永久效果分类 100～200 的优先级。这些分类取自原生登记表，不等同于 SpEffect 的 spCategory。

原生永久状态如 9700／9701、700600 的 effectEndurance=-1，不会因不断重置短计时器交换位置。有限时间效果自然倒计时时，相对时间通常也保持顺序；重新获得／刷新或数量变化时，原生图标移动仍可能发生。

## 原因及改动

三种自定义可用状态每 750ms 续期到 2 秒，用于联机副本失效与恢复处理。与“可用直到消耗”的含义相比，这个时间只是同步租期。按真实剩余租期排序时，独立刷新会反复改变大小关系。上版只为列表提供固定 2 秒排序键，漏掉 HUD，也没有采用原生永久状态的排列语义。

现在两处原生比较器共用 `status_sync::compare`，只在传给原函数的栈上副本中把以下三个效果的排序时间变为 -1：

| 效果 | ID | HUD 图标 |
| --- | --- | --- |
| 终极刷新（可用） | 95000403 | 20297 |
| 结晶外壳（可用） | 95000701 | 20408 |
| 逃跑计划（可用） | 95001203 | 20222 |

比较器仍执行原生代码，包括分类、同 ID 索引和多图标逻辑。原始条目、数量、有效时间、文字、冷却和清除条件不改；未涉及上述 ID 时直接传入原指针。没有改成实际永久 buff，避免取消现有联机失效处理。HUD 增加独立签名和五字节原跳转重定位检查；已存在的原生 E9 不能单独证明挂钩成功，加载验证要求跳转目标确实改变。

## 其他图标审计

从当前 dist 参数回读全部自定义 SpEffect 的 iconId、secondaryIconId、时长及相关字段。其余有限时间可见图标只有豪饮的 80 个独立 15 秒效果，以及受伤触发的 1 秒隐身 95000801。两者由实际喝瓶／受击触发，并非可用状态后台续期；保留原生聚合、层数与有时限排序。其余永久拥有状态本来就是 -1，隐藏冷却与标记不参与 HUD。所有自定义 secondaryIconId=-1。

## 验证边界

`tools/verify_hud_order_native.py` 将原 EXE 原始节和正常 PE 重定位映射到独立进程私有内存，以执行被 Arxan 分散的真实 7DF110；不附加到游戏，也不写游戏进程。索引零条目避开参数查询分支。复现原始时间翻转导致的换位，检查三种可用状态的所有时间组合、永久／临时原生效果、数量不变、同 ID 索引和 1500 帧独立续期，共 1761 项用例。

Rust 测试执行原始 82BA40 机器码和挂钩引擎生成的原调用跳板。两处永久分类查询调用在私有测试内替换为明确的登记表桩，用于检查常规永久类型和 100～200 优先类型；其余执行路径保留原字节。实际游戏中的登记表查询没有替换。另验证普通有时限效果保留原条目指针、续期节流及角色变化处理。

隔离排序、编译、签名及加载检查不能替代游戏画面验收。待验收：三种可用图标同时存在时，本人与队友 HUD 持续稳定；消耗后正常消失、冷却结束恢复；豪饮层数正确；阵亡复活后副本恢复正常。
