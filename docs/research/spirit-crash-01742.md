# 强化【死灵术】重复召唤崩溃调查（0.17.42）

## 现场与证据

2026-10-11 用户单人复仇者测试，施放绝招、灵魂显形之前崩溃。用户记得战场老将和结晶人；曾对墙召唤，一次未显形，最后一次在空地崩溃。不能据此把墙面或某个 BOSS 判定为根因。

Windows Application 1000 与两份转储对应本地时间 20:21:03（PID 12516）、20:32:17（PID 34004）。两者均为 `nightreign.exe+3981AC`，异常 C0000005，RCX=0，写地址 C。原生 `398190` 正在写 `RCX+C`；调用路径中的 `3AB810` 从物理模块 `+190` 取该对象。转储中的栈值扫描不是完整栈展开，不把所有候选地址当作真实调用帧。

NRHex 日志时间为 UTC。两次最后的 summon 成功返回分别为 12:21:01.958、12:32:16.341，约一秒后崩溃。前次召唤分别是 12:20:46.453、12:32:00.800，间隔约 15.5 秒。多次返回相同 handle `0x7022FFFFFFFF`。表明问题发生在新召唤返回之后，且伴随旧灵魂死亡后的槽位复用；不支持“创建函数内立即崩溃”的表述。

转储保留于 Windows CrashDumps；解析结果、原生反编译与修改前备份在 `.work/crash-spirit-01742`。转储未包含足够的对象堆内存，无法最终确认异常中的物理对象属于哪一次召唤。

## 已确认的实现错误

当前 EXE SHA256：`9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`。

原生 `3912D0` 调用 `3922C0` 选择空槽，再调用 `391DC0` 创建死灵。槽状态位于实现对象 `+58+i*50`：

| 状态 | 原生处理 |
| --- | --- |
| 0 | 等待加载与友方初始化 |
| 1 | 已初始化；死亡或卸载后由 `3922F0` 转为 2 |
| 2 | 尸体／退场计时；计满转为 3，发送 kind 2 消息 |
| 3 | 等待 `391780` 清理 |
| FF | 空闲，`3922C0` 唯一接受的值 |

`391780` 对状态 3 先调用 `4EA2D0` 移除碰撞记录，再调用 `51B2B0` 移除世界对象，最后写 FF。旧实现使用 `state > 1`，因此会提前选中 2、3。`3918D0` 发现该位置存在对象时会直接调用 `51B2B0`，绕过上述完整退场顺序。这是可确定的生命周期错误，与本次崩溃时序及物理对象空指针吻合；在实机复测前仍不能证明它是唯一原因。

## 修改

直接调用原生 `3922C0`，加入精确字节签名验证；只接受返回的 0～5。全部槽位占用或正在退场时，本次不调用创建，不消耗储存的灵魂，可在后续绝招重试。未改变 15 秒强制死亡、成功消耗灵魂、队伍击杀储存、前方 5 米的位置及原生网络消息。

仅在召唤尝试时记录六个状态与选择结果，便于后续复现核对。没有对全局物理函数加空指针绕过，也没有主动提前回收对象。

## 验证与边界

- 199 项 Rust 测试通过。原有完整创建 ABI 测试改为执行经验证的原生选择器机器码，包含 255 种非空状态拒绝、退场槽保护、12 个不同 NPC 描述符的重复生命周期，拒绝时无创建／网络调用、无槽数据改写。
- `tools/verify_spirit_slots_native.py` 执行真实选择器的 17,161 组输入，覆盖六槽 0／1／2／3／FF 的所有组合以及每槽所有 byte 值；只有 FF 可选，函数不写槽数据。
- 构建及当前 EXE 的 86 处签名检查结果见交付记录。
- 这些检查没有运行完整原生对象销毁或物理世界，不能代替实机崩溃复测。尚需连续召唤不同 BOSS、15 秒前后衔接、对墙／空地召唤和联机验证。对墙未显形是否为相同原因仍未确定；本次没有增加未经核对的地形寻路接口。

用户反馈天使的添翼、别停止咏唱“看起来表现都是正确的”，仅记录为本次单人表现反馈，不扩展成所有施法速度或联机验收。
