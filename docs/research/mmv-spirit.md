# MMV 强化死灵术适配

适配仍共用 `spirit.rs`、原生击杀结算和原生召唤流程，不引入另一套计时或最后一击归属规则。MMV 源目录只读；构建只修改 NRHex 兼容层。

## 数据与模型

- 重新从合并后的 MMV `NpcParam` 生成全部灵魂副本，包括原先已有的 3,100 条映射。旧副本不再沿用原版 HP、攻击、特效等数据。
- 保留已有私有 ID，从原范围末尾追加 MMV 映射。当前新增 5,706 条可用 NPC 参数映射；**这不是 5,706 种可捕获强敌**，捕获仍须通过强敌资格、有效 AI 和原生击杀结算。MMV 编号登记在 `compat/mmv/spirit-npc-ids.json`，只追加、不因源 ID 排序而移动既有映射；运行时查找表独立按源 ID 排序。
- 副本仍禁用卢恩、物品、再次死灵化和团队奖励，并保持原本的玩家侧伤害分类。原生敌人参数及现有灵魂伤害倍率、耗血速度不变。
- 从 147 张 MMV 地图读取实际 `ModelName`。例如盖尔第一阶段 `62000001 → c6201`、洛格力斯 `901300011 → c9013`，不能套用 `npc / 10000 % 10000`。
- 从 MMV 事件及原生公共函数解析 BOSS 血条的角色／组绑定，当前有 279 条可映射 NPC 变体；同时保留原版强敌目录及运行时精英效果标记。`isSoulGetByBoss`、`threatLv` 或名字本身均不构成新增捕获资格。
- 不把所有带 BOSS 奖励标志的坐骑、蛇形辅助对象、召唤物自动纳入。组血条允许组内战斗成员，仍由原生结算确认击杀；不保证组内每个角色都是可独立工作的完整 BOSS。

## 明确边界

829 条新增参数暂不建立召唤映射：实际模型或无地图证据时的模型前缀指向 `c0000/c1000`，以及缺少地图模型证据的扩展编号。不能用普通 NPC 的 `chara_init=-1` 去创建玩家角色模型。`NpcParam.npcType=1` 表示 Boss，**不是人形／玩家初始化类型**，不能据此排除。两个模型存在歧义的旧参数保持既有行为，不凭任一地图覆盖。

复制一名敌人的参数、模型和当前 AI，不等于复制其原地图事件、配对坐骑、阶段转换或场景机关。本次不添加这些专属控制流程，不能据此宣称全部多阶段 BOSS 已完成实测。

联机继续使用原生 `0x1B` 创建通知；双方必须使用同一版兼容层 DLL 和参数包。既有私有 ID 不变，新目录的模型逆向查询不再依赖“源 ID 排序等于私有 ID 顺序”。

## 构建与验证

`MmvSpirit.Export → build_mmv_spirit.py → MmvSpirit.Apply` 在基础参数合并之后、其他目标表导出之前执行。映射通过 `NRHEX_SPIRIT_DATA` 编译；独立版默认空目标扩展，发行构建显式固定原版表。

构建校验源文件散列、私有 ID 冲突和模型歧义。重新加密后回读所有参数，确认私有副本之外的 NPC 和其他 binder 成员未改动。Python 回归覆盖事件参数展开、无关辅助角色、模型与 ID 映射、碰撞拒绝及稳定排序；Rust 回归覆盖捕获、存储、消耗、创建参数和模型查询。原生模型、槽位、空间检测、伤害分类及退场的隔离夹具通过。

这些是静态、状态机与原生调用验证。新增敌人的捕获／AI／退场，以及双方可见性，需要在对应 MMV 遭遇中验证。

本轮验证：独立版与 MMV 各 29 项 Rust 测试通过（原生 EXE 专用测试未在普通测试集中运行），6 项目录回归通过；完整 MMV 测试版构建通过。仅部署 DLL 与参数，启动后确认 ACTIVE=1，击杀结算、联机结算接收、模型转换三处钩子均指向当前 DLL。尚未完成新增敌人的游戏内召唤或双人验证。
