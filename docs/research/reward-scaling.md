# 运行时奖励与扩容

适用EXE SHA-256：`9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`；regulation内部版本`10350000`。原生代码隔离执行、参数回读和虚拟目录测试不代表实际游戏或联机验收。

## 掉落表容量

旧方案为每种有序三选一保存三行。28项对应`28×27×26×3=58,968`行，原生及红包另占2,747行，总计61,715。PARAM头的行数为16位字段；继续增加能力会超过65,535。

当前仅保留原生三行模板`95200000..95200002`。DLL在抽取时直接无放回选出三项，再在原生创建节点之前填入Goods ID。敌人掉落表只需2,750行；增加海克斯不增加模板行数。每项能力仍有正常Goods、永久能力、附加效果及ItemTable等线性增长的数据。

`reward_cycle.rs`以动态集合和候选列表代替全排列。普通抽取逐项使用无偏随机索引，并从本次候选中移除已选项。旧轮尾部1～2项先展示，再用新轮补足；已拥有、角色／地形限制、展示历史和当前可见项继续参与过滤。候选存储为O(N)，不再分配O(N³)排列。

## 原生描述符

已核对原生`576BD0..576E9F`：每个描述符对应一个选择，`+A9`由该选择的循环序号写入；`+58`含奖励种类、网络位及UID字段，`+5C`等保留原生分组标识，`+AA`含启用／拥有槽，`+B8`为掉落来源。

本地`5759E0→57D0A0→5803C0`创建时，`570410(node+20,descriptor)`复制描述符，因此`descriptor+8`成为`node+28`的物品编号。`570FC0`再按UID读取该节点的ItemData。当前只在已有限定TLS调用范围内临时替换`+8`、清除`+58 bit4`，原生返回后恢复两处。其他玩家、其他管理器／掉落表／奖励类型不改。选项序号决定替换内容，成功计数不承担排序；重复回调不能再次提交相同序号。

零创建允许重新尝试；部分创建已经发布，按已发放处理并记录错误，不重发整组。原生继续负责UID、分组、世界显示、菜单和确认领取；实际菜单／联机仍待验收。

## 展示记录与原生保存容量

原生保存类别表位于EXE RVA`2BE6DC0`；类别10的起点／容量为`31／50`，与其他类别10效果共享。单纯扩大运行时整数或动态集合，不能解除这个原生保存限制。

展示记录改为按字节保存。稳定登记表`HistoricalOwners`保留停用项位置，只能追加；`HISTORY_BITS`把当前目录下标映射到稳定登记位。非零字节使用`96000000 + group*256 + value`，零字节不添加效果。每组255条参数候选均为中性、隐藏、死亡保留及禁止网络同步的保存效果；任一时刻每组只需一个非零值。

当前29个登记位（含一个停用保留位）只需4条活动记录，替代28条单项记录；96项虚拟目录含97个登记位，最多13条。通常一局仅展示部分能力，只有非零字节占用保存槽。参数候选行数、实际活动保存条数和目录项数必须区分。游戏单表行数及共享保存区容量仍存在，本实现降低占用，不修改原生文件格式或保存结构。

运行时每250毫秒核对实际记录，包括仅包含停用位、解码为空的残余记录。写入与删除跨帧时以已提交的集合为准，不能被不完整的原生快照覆盖；新轮不恢复旧字节。原生新远征／圆桌通知`95002825`保持原样；收到通知后只清理实际存在的记录，确认清空再消费通知，避免生成数千条全值清理指令。普通死亡、复活或对象地址变化不清空历史。

## 验证与维护

常规测试覆盖32／64／128边界、1000项虚拟目录抽取／轮换、所有角色过滤、尾轮顺序、无重复抽取、小候选池、随机失败、字节编码和原生延迟确认。五项小目录穷举证明随机索引序列恰好覆盖所有不同三元组一次，无需在发行数据中保存排列。1000项为运行时及编解码测试，不声称1000项全部置位时仍能装进原生50条共享保存区。

`HexBuild --reward-template-stage`用实际元数据、压缩记录及reset通知生成器模拟28／64／96／160／256项。回读比较全部保留掉落行、全部非历史效果行及其他表，原生和红包数据保留；1020条当前压缩参数替代28条旧记录。事件、FMG、动作及配置文件不改。

`verify_reward_template.py`运行编译后的5759E0钩子、原生网络位谓词、描述符复制和UID物品读取。分配／分组／渲染由调用真实复制函数的夹具替代，UID查找也使用夹具。覆盖三名本机槽位、乱序描述符、完整字段保留、回调去重、无关路径、非法序号和创建失败。未访问游戏进程，实际球显示、领取、单栏刷新、复活及联机均需在配套DLL／参数的新远征中验收。

新增能力应追加稳定登记ID，选择未占用的效果ID，避免占用`96000000`起的历史编码区；修改机制与双语文案后完整构建。旧全排列增量入口已退役，不能再生成或安装旧排列目录；不进行旧排列球或旧格式展示记录的跨版本迁移。
