# 刷怪笼红化与塔楼奖励（0.17.19）

## 原生红化名额的换算

原生`ChaosMatchingMutationCategoryParam`的野外BOSS类别120按地图指定名额；六种地图的深度1均为0，深度2～5的名额相同。刷怪笼没有完整地图的分配过程，因此按用户确认的规则，将名额除以该地图适用的`ChaosMatchingMutationEnemyTableParam.mutationCount`总和，作为每次刷出的独立红化概率。它是按表换算的近似值，不能视为原生地图上每只BOSS的精确边际概率。

| 地图标记 | 适用名额总数 | 深度1 | 深度2～5名额 | 换算概率 |
| --- | ---: | ---: | ---: | ---: |
| 7600 | 55 | 0 | 5 | 9.09% |
| 7601 | 64 | 0 | 6 | 9.375% |
| 7602 | 66 | 0 | 7 | 10.61% |
| 7603 | 55 | 0 | 7 | 12.73% |
| 7604 | 55 | 0 | 5 | 9.09% |
| 7605 | 67 | 0 | 9 | 13.43% |

普通模式没有深夜效果，因此不红化。大空洞仍不能抽到刷怪笼，表中保留原生类别以完整核对来源。

房主在生成后根据角色实际深夜档位抽取，使用已分配的7650～7686、7700～7736地图标记同步红化和决策。客户端不抽取；重载沿用已决定的结果，胜利时清除，下一次生成重新抽取。原来5秒胜利和20秒角色清理的安排保留。

中性效果95001602标识本次红化。DLL仅处理95300000～95300036复制NPC，通过原生角色红化位`ChrIns+1FB bit0`启用注册在`ChrIns+5D8`的红化效果来源。其原生读取函数4FFF30读取NPC的`chaosMatchingSpEffectSetParamId`，原生刷新函数50ED10应用对应效果；已登记的前两个效果存在后不再刷新。各BOSS使用自己的4480～4483视觉和7220／7230／7240战斗效果。原生倍率包含HP、伤害和卢恩，未统一手写一种红化倍率，也未调整日程、基础HP或联机人数修正。

原生奖励函数3DF760优先检查地图掉落覆盖，没有覆盖且角色红化时，E95360读取`chaosMatchingRewardLotId`（参数+338）。监牢／野外复制NPC保留自己的原生红化表，塔楼复制NPC使用下述武器奖励作为普通和红化奖励；原生红化效果的卢恩倍率继续生效。

## 为什么同一只BOSS在塔楼会掉武器

这7种地图复用守夜BOSS模板。NPC的默认6200000／6210000表经ItemTable4200210／4200300只提供锻体词条，因此“生成了一个球”不能证明生成了塔楼武器奖励。原来的刷怪笼仅复制这份基础奖励，确实漏掉了地图上的覆盖。

地图变体2的构造事件调用90015442等塔楼流程；90015070等待SmallBaseAttached及MapVariationId=2后启用00300／00301奖励标记。[NR EMEDF](https://soulsmods.github.io/emedf/nr-emedf.html)可用于核对1012[1]、12[1]和3[49]的参数类型；调用关系、分支和具体值来自本项目保留的原生事件。

当前安装的SoulsFormats读取敌人类型数据时遗漏尾部，所以解析对象／重新写出的字节里看不到奖励覆盖，原始解压MSB里却有。生成器现在从唯一角色EntityID定位，核对原NPC／AI编号及源文件哈希，再读取Entity位置+A0～AC的两组标记和掉落表。原生E35590取敌人类型数据，E356B0读取类型数据+50/+54和+58/+5C，依标记选择奖励，与原MSB字节对应。

| --- | ---: | ---: |
| 树熔炉 | 6850000 | 6851000 |
| 舞娘 | 6850000 | 6851000 |
| 蒙葛特 | 6851000 | 6852000 |
| 葛瑞克 | 6850000 | 6851000 |
| 石像鬼 | 6850000 | 6851000 |
| 大土龙 | 6851000 | 6852000 |
| 坠星兽 | 6851000 | 6852000 |

刷怪笼没有塔楼楼层和附着点，采用各BOSS第一档原生塔楼奖励。前两项引用原生随机武器池，第三项保留原生词条选择；连续刷取不受一次性领取标记限制。只修改7个复制NPC的普通／红化奖励字段，原版塔楼和守夜NPC不变。MSB尾部还存在备用AI编号，已记录但本次未改变复制角色的AI。

## 验证范围

参数加密后重开，逐行逐字段限定改动；四地图恢复原始部分后与输入一致；原有事件、文本、用户CSV／INI和地图布局保持一致。158项Rust测试、54个当前EXE签名、15984组地图／深度／房主／客户端／重载选择用例通过。原生4FFF30和E95360在假角色／参数内存中隔离执行，覆盖全部256种红化位组合及空引用，外部表查询重定位到本地夹具。原生标记存储函数也隔离核对新标记组的置位／清除。

以上为静态、产物回读和隔离验证；没有启动游戏验证新红化、实际球内容或联机同步。临时血量诊断代码和dist运行入口已删除，0.17.18历史实測证据仅留在项目私有研究目录。
