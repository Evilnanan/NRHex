# 原生回收槽的再次受击行为

核对对象：EXE SHA-256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`，2026-10-17。执行原生机器码的离线隔离测试，不代表游戏内HUD观察。

## 结论

不能把原生槽解释成每次伤害简单累加、全部额度共同获得新窗口。原生分开保存总额度（stats+168）、受保护额度（+16C）、保护剩余时间（+170）、待恢复量（+174）。

新命中重置标志成立时，426B74～426B84先清零+16C／+170／+174，保留+168；后续把新损伤乘原生回收比例加入总量及受保护量，并刷新通常4秒的窗口。4289C0每次更新时，如果总量大于受保护量，以最大HP×dt的速率削减总量，直到受保护量。窗口结束后保护量归零，剩余总量继续按相同速度衰减。

因此新命中后旧额度在该瞬间仍计入总槽，但立即失去衰减保护，很快只剩最近一次受保护的损伤；攻击足够及时仍可能在旧额度消失前回收一部分。不是瞬间完整覆盖，也不是全部叠加并续期。

## 调用点和例外

玩家43D260的43D6A9调用共享43BE60，43BF69检查正损伤并通过4B2D50／4BFCF0比较及更新原生命中身份对；新记录时43BF97设置R9B=1，经426130的426144／426175转为setter的R8B重置标志。相同记录分支可传0，不应把所有内部扣血调用都视为一笔全新受击。

原生setter同时接受回收比例、窗口倍率与窗口刷新标志；重置旧保护和刷新窗口不是同一个参数。此前隔离测试多使用reset=0，确实能观察到受保护额度累加，但不能代表普通新命中的reset=1路径。

## 复现结果

无Mod hook，HP上限1000。先受200伤害，过1秒，再受100伤害，原生比例／窗口倍率均为1：

| 时点 | 当前HP | 总可回收 | 受保护额度 |
| --- | ---: | ---: | ---: |
| 第一击后 | 800 | 200 | 200 |
| 第二击后，reset=1 | 700 | 300 | 100 |
| 再过0.1秒 | 700 | 200 | 100 |
| 再过0.1秒 | 700 | 100 | 100 |
| 此时申请回收999并结算 | 800 | 0 | 0 |

对照reset=0：第二击后总额度和保护额度均为300；过0.2秒仍为300，申请回收可恢复至1000HP。

最小探针为 `tools/probe_regain_rehit.rs`。在Windows Rust工具链下用 `rustc --edition=2021 -O tools/probe_regain_rehit.rs -o work/regain-recheck.exe` 编译，传入上述原始EXE路径运行；Linux可使用x86_64-pc-windows-gnu与Wine。探针在私有内存映射PE，执行原生426B00／4275A0／4289C0，仅以桩替代权威、角色及449状态查询，不访问运行中的游戏。原生清除／累加／衰减及回血限额代码均未修改。

## 死亡之舞的共享保护

初版0.17.146仅在426BAE拦截缓扣，原生426B79清理发生得更早，所以第二次新命中仍会使旧份额失去保护；每帧支付使用reset=0不能补回已经被清掉的旧保护。

当前实现额外在426B79安装有作用域的中途hook：只对本机存活持有者、规范stats、真实HP下降及有效449状态，跳过清零+16C／+170的单条11字节指令。426B84清零待回血+174继续原样执行。其余来源、非持有者、濒死／复活和状态拒绝均转回原指令。该拦截不直接增加额度，也不写入新计时；之后每笔实际缓扣沿原生setter累加额度及刷新窗口，停止支付后正常过期。

保留现有受保护值而不是把总槽写回保护值，可避免重保已经过期的旧额度。普通回血仍会按当前缺血量收缩总槽和保护量；不可回收伤害不增加额度、不更新窗口。一秒伤害队列依然逐击独立，回收保护采用原生共享窗口。

`src/death_dance_native_tests.rs`将两个正式编译的hook安装到隔离映射的当前EXE，验证真实reset=1连续受击、原生待回血取消、共享续期／自然过期、过期旧份额不复活、普通回血限幅、不可回收损伤，以及非持有者／远端／濒死／原生449拒绝的回退；由 `tools/verify_death_dance.py` 调用。不修改原生更新／排队／消费代码，不代表实机和联机验收。

## 持续扣血的无敌与锁血

用户实测报告：旧缓扣在绝招无敌过程中仍能扣至死亡，复仇者锁血也无法阻止。该反馈只覆盖这两个失败场景；后续修复尚未进行实机验收。

原因是缓扣直接使用426B00，而原生持续SpEffect结算431B30先在431BDF调用角色虚函数+210（参数0）判断扣血无敌；431C47／431C70／431E01再使用426130增减HP入口。426130对负变动再次检查+210，继而调用427BC0；后者在预期HP不大于0时检查属性标志、原生state143／235及行为模块+58位17，将锁血结果限制为1HP，最终才进入426B00。玩家+210为66D410，经3D3E20检查扣血无敌状态并检查玩家+6E4免疫计时，不进入普通碰撞免疫3D3DB0／3DF380的攻击引用与掩码判断。

当前缓扣改为调用426130(stats,-amount,0,0,rate,window,refresh)，保留每笔原生回收参数、reset=0及43CED0结算通知。时间由用户要求改为一秒，仍逐击独立；被无敌抵消的到期份额不积压、不产生回收槽，锁血只让实际失去的HP进入槽。既有恢复／共享保护不变。

隔离执行增加真实426130、427BC0、66D410、3D3E20与模块getter路径，覆盖六种扣血免疫、五种原生最低HP机制、免伤结束无补扣、碰撞专用状态与持续扣血区别、一秒末结清及无保护的致死扣血。权威、拥有／state存在及完成通知出口仍为夹具；这不等于已验证绝招动画、复仇者动作或联机全过程。

缓扣仍按每帧dt推进累计整数份额，使HP在一秒内平滑流失；只复用原生保护判断，不复制毒／腐败的motionInterval或周期跳伤时序。60Hz隔离用例逐帧核对扣血及通知次数。
