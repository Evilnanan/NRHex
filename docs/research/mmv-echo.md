# MMV 回响施放适配

2026-10-26，Mayhem Augments。新增 39 个法祷、96 个根发射入口；同一源码按目标注入目录，独立版保持原有支持范围和数值。延迟仍为 0.5 秒，FP／精力消耗与文案不变。没有修改 MMV 原包或原生法术参数。

## 处理方式

- 从合并参数读取 Magic 的实际直接引用，只登记经过审查的根。命中派生和计时子弹仍由原生链生成，不对每颗后续弹体再回响。公共空辅助根 10999999、自己施加状态的辅助根均排除。
- 六种持续或蓄力配置沿用逐轮初始化捕获：只复制成功生成的轮次，记录该轮每颗弹体的位置和方向，停止施放后排空已产生的延迟轮次，不凭空续射。进入此分支还需原生生成组为持续组，不能仅凭菜单持续耗蓝字段就把所有发射当作持续流。
- 混合型法术按具体根区分：贝勒的残虐只有原地爆发使用范围回放，外扩段仍保留飞行姿态；双月、熔炉花、贝勒焰雷的范围段及梅瑟莫火球爆发分别保留原地姿态。不会对整种法术清空目标。
- 39 个新法祷的回响不借用首发的共享命中列表；有整次施法记录时，沿现有分配器生成独立回响记录。同轮多根继续共享新的整次施法记录，持续轮次继续共享自己的列表。原记录不清空、参数去重开关不关闭。
- 远方之恢复重放实际治疗投射物及其原生落地链，保持原生治疗量和目标过滤。没有新增个人自疗副本。
- 只复制弹体及其派生视觉，不重新播放施术者动作或 TAE 身体特效。混合型法术不承诺动作本体伤害或整段角色动画也出现第二遍。

## 仍不重放的新增记录

- **猎命镰刀、鲁格利亚的咆哮**：前者无 Magic 弹体引用，后者只引用公共空辅助根。不能通过复制空根重现角色动作攻击；这轮未新增直接攻击回放系统。
- **黄金树庇佑、卡利亚恩惠、发狂扩散**：本次读取的直接根不构成对敌攻击链，属于个人效果／控制入口，不重复施加自身状态。
- 四条无名称的内部 Magic 记录 3730100～3730400：没有可重放的 Magic 弹体入口。
- 原有五个明确例外保持：爆破岩盘、彗星亚兹勒、奔放结晶、陨石、艾斯提陨石。既有个人恢复／增益／附魔限制保持；原有群体辅助回响也保留。

## 构建与复核

`compat/mmv/echo-spells.json` 保存 48 条新增记录的完整取舍，以及 Magic、全部直接根及其可达链、攻击行的审查指纹。允许名字变化，但机制字段变化、新增 Magic 或歧义行会要求重新审查。不能将公共辅助根、子弹体或持续附着的无限寿命根直接加入目录。

`build-mmv.ps1` 在导出合并参数后运行生成器，检查参数导出哈希对应当前暂存资源，再通过 `NRHEX_ECHO_DATA` 编译目标表。独立版的默认表不包含 MMV 条目；发行构建显式选择原版数据，避免继承其他构建的环境变量。

```powershell
python -X utf8 tools/build_echo_cast.py --check
python -X utf8 tools/build_mmv_echo.py
python -X utf8 -m unittest discover -s tools -p test_mmv_echo.py
```

### 神鸟羽毛持续耗精现场核对

用户试用后反馈暂未发现问题，随后询问持续引导耗精。2026-10-26，PID 13740 确认加载上述 MMV DLL，耗精钩子仍在；按用户反馈的神鸟羽毛持续施放时段，只读采样捕获连续三段每次扣 4 点精力，共 61 次，持有回响标记 95003500。后续独立采样读取的当前 Magic 为 2007740。记录位于 `work/compat/mmv/echo-stamina/`，没有替换 DLL 或写入游戏内存，采样已结束。

当前 MMV 神鸟羽毛参数 `stamina=3`、`stamina_charge=0`；实际循环通过独立的默认费用引用消费 3 点，而两条发射引用 `consumeType=2` 自身不扣费。回响在费用构造末尾使用整数 `cost + cost/2`，因此 3 点变为 4 点。现场证明持续阶段也增加了耗精，并非只在起手生效；但低费用向下取整使该例的实际增幅为约 33.3%，不是精确的 50%。本次没有改变这个已有取整规则。

采样时其他持续法术按原生实际提交的费用类型处理：正费用乘 1.5 后向下取整，原本为零的续段不凭空收费。原生消费者 384A30 读取 context+C0 的缓存值；已有回归覆盖同一缓存多次消费，不会每次再次乘 1.5。未将神鸟羽毛的现场结果扩展为所有持续法术均完成实测。

### 四舍五入调整

随后按用户要求将共享耗精逻辑改为四舍五入，正数半点进位：`cost + cost/2 + cost%2`，最后饱和到 i32 上限。神鸟羽毛基础 3 点因此变为 5 点；35 点变为 53 点，46 点仍为 69 点。原生补正后的最终整数费用只处理一次，零费用、负值和非拥有者保持原行为。上方 61 次扣 4 点是调整前的实测，不代表调整后游戏验收。

四舍五入调整通过编译后原生费用／ABI 回归，包括 1／2／3／4 点、原生倍率补正、缓存重复消费与免耗保护。仅更新 MMV 测试版 DLL 并重启，PID 11988 的 ACTIVE=1，耗精钩子确认指向新 DLL；SHA-256 为 `525aeaf83654e3258f896b17fd19a9a6e5e6b039e0411336490a0a8bdbe34fc4`。部署与加载记录为 `work/compat/mmv/echo-stamina/rounding-deployment.json`、`rounding-loaded.json`。独立版共享源码已同步，独立版及群友版 DLL 本轮未部署。
