# 0.17.27 联机与动作修复

用户双人原生联机经私服测试，房主和队友分别持有刷怪笼都出现重复生成、两颗奖励球，以及双方黑雾／血条互斥。血量偏低是体感反馈，尚无这一轮最终血量实测。

## 刷怪笼

旧选择器、生成和结算事件没有明确的房主执行限制。现在事件关闭自动同步后，以1003[14]（OtherWorld=1、End=0）结束远端执行；交互仅提交共享请求位。房主在第一次等待帧前预约used与busy，再抽取和提交ready。请求期间的重复通知不能再次抽取，原生监牢的钥匙和非持有者分支保留。

生成后由房主设置2004[28]网络控制权8192，依据原生9005800的房主BOSS分支。所有参数中的原生联机修正引用保持原样；此前只有引用，刷怪笼没有执行原生2009[4]属性激活。新增流程按90015022的7999标记保护激活，一只新生成单位只启用一次。没有另加手工血量倍率，也没有改变日程、深夜或红化系数。原生 `MultiPlayCorrectionParam` 一、二、三名队友配置回读记录在 `dist/reports/coop-parameter-validation.json`。

旧出场事件等本地模型加载后才判断spawned；慢的一端可能把新出场误判为已经开始的战斗。现在在ready与choice成立时保存新出场状态，该条件通过主等待图参与编译，随后才解除本地backread移除并等待模型。与已开始的战斗重连仍直接显形；新出场即使晚到9秒也保留黑雾。血条仍等各端自己的shown标记，沿用原生血条槽位与关联，不依赖副本AI状态。

保留50种遭遇、84个单位、骑乘、共用或复数血条、塔楼武器奖励、整组胜利以及5秒结算／20秒清理。四份MSB地图逐字节与输入一致；common事件、所有无关事件与构造器不变。参数包仅增加两条隐藏战技通知行，其余参数表与既有行不变。

## 百般武艺与嘉豪

旧百般武艺等待两个没有战技节点的更新帧。准备架势持续发送busy，出招后立即再次准备就能让pending一直不被消费。新的隐藏USED标记让六个原生准备回调识别已使用战技；重新准备时发送PREPARE通知，消费pending、重铸一次，并执行原生架势结束动作，阻止继续沿用已缓存的旧战技类型。没有出招的准备不重铸；连续攻击架势10／11／25／239保持原连段退出机制。原始武器为风暴管束者或小圆盾格挡的保护规则不变。

嘉豪的后跃判定原来只检查129，远程后跃也可能带此分类。现在要求129与130（近战）同时成立，并排除105（远程）。伤害增幅和命中回复共用此判定，不根据命中时当前手持武器猜测，避免已发射子弹在切武器后绕过限制。

## 可用图标排序

原生830EA0收集20字节显示条目后经82BA40排序。条目依次是效果ID、图标、索引、剩余时长和层数；不同效果先依剩余时长排序。2秒可用提示分别续期时，顺序因时间大小交替翻转。

新挂钩只给95000403／95000701／95001203构造临时显示排序副本，将排序时长固定为2，再交给原生比较函数。原图标、层数、说明、实际寿命、效果链与玩法计时不变；其余效果沿用原值。恒定键仍由原生函数排序，避免只强行交换一对条目造成非传递比较。

`data/reference/ui/status-sort.bin` 是当前1.3.3.0 EXE、RVA82BA40的555字节原始比较函数，SHA256 `ffb545b68af56a9d9e6f92fe3de44f336e39b4692b8f520c032bdfaae6c5af21`。隔离测试只走有限时长、索引0以及同ID索引分支，避开游戏全局依赖，复现原排序翻转并验证修复后的稳定顺序及输入不变。
