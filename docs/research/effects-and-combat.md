# 效果、显示与战斗结算

适用于 Buff、命中条件、伤害/吸血、攻击分类和视觉复用。结论提炼自 Nightreign 参数、原生调用链与游戏反馈；不包含具体 Mod 的数值或设计。枚举和字段的实际执行方式需按目标版本确认。

## 分清数据角色

| 数据 | 主要用途 | 常见混淆 |
| --- | --- | --- |
| `SpEffectParam` | 运行时数值、状态、持续/周期、触发链和视觉引用 | 效果 ID 与 `stateInfo` 是两种身份；状态相同不代表属于同一功能 |
| `AttachEffectParam` | 装备/词条的被动效果引用及展示 | 仅创建展示行不等于授予能力；一个词条可能引用多个效果 |
| `PermanentBuffParam` | 潜在能力的大图标、领取展示及效果引用 | 弹出提示不保证已经进入完整领取链 |
| `SpEffectVfxParam` | 初始、持续、结束 SFX 和绑定点等 | `SpEffectParam.vfxId` 通常引用这一行，不是可随意替换的原始 SFX 编号 |
| FMG | 名称、说明、领取提示等文本 | 临时状态与永久奖励可能从不同 binder/FMG 取文字 |

把永久拥有者、临时实际效果、冷却、持久记录、视觉效果分开，便于明确哪些需要保存、清除、显示或同步。纯视觉行不应再携带来源词条的攻击倍率、回血、回蓝或条件。

复制参数前检查 `effectEndurance`、`motionInterval`、`saveCategory`、`spCategory/categoryPriority`、条件字段、适用目标、替换/周期效果、图标/文本、VFX 以及所有倍率。看起来通用的模板仍可能带生命上限加成等隐含收益。静态效果量纲、字段宽度、默认值与负号不能凭命名猜测。

条件效果可由参数、事件、HKS 或 native 决定是否生效。复制原生“满血时增益”时，保留所需倍率和适用范围，移除满血条件需检查完整条件链；不要复制整行后只改持续时间。

## 倍率、恢复与硬直是不同机制

- 五类 `physics/magic/fire/thunder/darkAttackRate` 与对应 `AttackPowerRate` 不可互换。已核对的原生百分比增攻词条使用前者；后者改变防御计算前的攻击参数，最终伤害通常不是线性百分比。文本里写“攻击力”不能决定字段选型。
- 匹配原生处理时，同时核对 `magParamChange`、`miracleParamChange`、`shamanParamChange` 等法术适用标志，以及分类/使用方式的过滤条件。
- `DamageCutRate` 在已验证路径中表示剩余承伤倍率：减伤比例为 `r` 时设置 `1-r`，承伤倍数为 `k` 时设置 `k`。物理分斩击、打击、突刺、普通，元素另有魔力、火、雷、圣；“全部伤害”需检查覆盖的全部字段及特殊来源。
- 属性加点还经过武器/法术补正与敌方防御，其收益不等于固定伤害倍率。
- 在已核对的即时恢复行中，`changeHpPoint/changeMpPoint` 的负值表示恢复，正值表示消耗；百分比、固定值及最大值限制需分别验证。持续恢复的每跳量与间隔一起决定每秒速率。
- HP 减伤、削韧、冲击等级和防打断不是同一项。降低 `saReceiveDamageRate` 不自动取消反应；原生防打断路径还查专用 `spCategory` 与 `dmgLv_*` 反应映射。该已核对路径按最低 `categoryPriority` 选行，不要假定全游戏类别都按“数值越高优先级越高”处理。
- 优先复用完成限幅、状态更新和满值通知的原生充能/恢复 API。函数已返回或效果已添加，可能仍被动作期间的禁止状态拒绝、或被后续更新清零；需要结果回读，必要时下一帧再次确认。

## 攻击分类与缓存顺序

原生攻击有可并存的分类位掩码，不是“近战/魔法/战技”三选一。已核对的掩码为 256 位；追加分类应 OR 对应位，保留原有分类。当前版本可用的研究锚点如下，更新版本时从原生词条和谓词重新确认：

| 分类 | 已核对编号 |
| --- | --- |
| 跳跃攻击 | 102 |
| 近战适用范围 | 130 |
| 战技适用范围 | 111、112 |

不能以物理伤害、距离、武器类型或“存在 Bullet”代替原生分类。法术可能造成物理伤害，攻击也可能同时拥有多个标签。

分类加上后增益仍不生效时，沿完整路径检查：来源描述符构造 → 使用方式/法术适用过滤 → 分类谓词 → 倍率聚合与缓存 → 命中描述符复制 → 接收者结算。普通 AttackRate 在命中创建前就可能缓存；只改后面的命中掩码不足以补算已跳过的增益。

法术适用类型的筛选还可能早于分类判断。不要把整个法术描述符伪装为武器，否则会改变其他效果的适用条件。可在原查询失败后，仅对指定的新增分类复制查询描述符，调整这次查询的类型，再交给原谓词判断；原查询成功的情况不可重复相乘，其他武器/目标条件仍由原生保留。此路线必须验证使用类型、原有标签、限制条件和倍率缓存。

构建时追踪 `Magic` 的引用类型与 `refId*`，继续遍历 `Bullet` 的子弹链和 `BehaviorParam`，最后确定 `AtkParam_Pc/Npc`。处理循环、重复引用、范围/蓄力子攻击和共享攻击 ID。攻击 ID 不一定唯一确定法术，武器和法术也可能共用子弹；结合参数表类别、原生来源和运行采样消除歧义。仅静态白名单不能保证覆盖附魔、间接召唤、持续场地和所有新法术。

射程估算可结合速度、加速度/速度上限、寿命、碰撞半径，但不能把 `Bullet.dist` 直接认作射程；它可能是衰减阈值。追踪、发射偏移、分裂、地形、射线和持续碰撞使估算偏离实战。保留估算与人工配置的区别，不在构建时用估算覆盖用户值。

## 在正确的命中阶段修改

先确认回调里的来源、接收者与对象类型；环境/弹体等通用来源指针不能直接当 `ChrIns` 解引用。本地玩家限制应先比较身份，再读取玩家专有模块。

从目标字段的写入者追到所有读取者，选在足够早且覆盖预期接收者的位置修改。有的玩家防御分支被普通 NPC 跳过；一个玩家受击 hook 不自动适用于玩家攻击 NPC。

HP 伤害值、实际 HP 损失、冲击反应、状态积累、失效标记与显示数字相互独立：

- 用原生失效位取消命中时，确认 HP 和冲击消费者都读取它；仅把 HP 伤害设零不能宣称完整免疫。异常、抓取、环境和直接死亡需另查覆盖。
- 失效的命中可能保留正的伤害元数据，原生“受损”词条也可能据此触发。设计要求“受击”或“实际失血”时，应选对应信号。
- 伤害飘字可能读取残留元数据，与实际扣血不同。显示修正单独处理，不用飘字判断命中是否扣血。
- 吸血需明确按实际失血还是完整命中伤害计算。前者会截断溢出，也会拒绝锁血目标；后者可包含过量伤害，原生隐士绝招直接使用完整命中伤害。锁血导致不掉血与攻击免疫是不同条件，不能仅凭 HP 前后差排除无效命中；需结合原生有效命中路径和攻击失效位。整数取整、上限和累计队列要有明确规则。
- 多段、多目标、复制/网络重放可能多次读取同一攻击。需要逐段计算还是整次动作锁定必须来自设计，不能把任意短 CD 解释为准确“一次攻击”。

冲击等级是离散反应类型，不能按编号大小当线性强度。只改每次命中输入可保留敌方抗性、霸体和原生反应映射；不要为个人 Buff 全局修改共享 AtkParam。

若命中构造后还会缓存、复制或重放，临时改值再恢复会使这些路径看到原值。将拥有者专属改动放在确认来源的构造阶段，保留到该命中生命周期结束，可覆盖后续副本；同时防止重入重复映射。适合临时查询的改动仍需保存/恢复原值，区分这两种生命周期。

## 图标、文本与特效

大图标和小图标来自独立 atlas。`PermanentBuffParam.iconId` 用于选择/获得展示，`AttachEffectParam.statusIconId` 与 `SpEffectParam.iconId` 用于词条/状态展示。编号相似不保证两个库都有该纹理；某些潜在能力家族存在编号偏移关系，仅可对已核对条目使用。

从 layout 的名称、坐标和尺寸裁出 TPF/DDS 图标，交叉查看实际 PARAM 引用与 FMG 文案。图标可被多个词条共享，本身不赋予机制；未找到命名引用的素材不能强行标为某效果。缺图先检查图标库和 atlas 是否存在，不先改 buff 逻辑。

永久奖励的文本查 `item*.msgbnd` 中 `AttachEffectName/Info`、`PermanentBuffName/Info/Caption`；临时状态的文本还需查 `menu*.msgbnd` 的 `SpEffectName/Info`。只填名字会留下占位说明。沿 `attachTextId/spEffectTextId_*` 验证实际引用，而非假定所有层共用行 ID。按目标语言生成并回读，保留未编辑 FMG 和 binder 成员。

复用 VFX 前查 `SpEffectVfxParam` 的初始、持续、结束效果和绑定点。短寿命反复续期可能每次播结束/破碎特效；需要持续存在的护盾等视觉可沿原生受击删除条件处理，例如核对 `deleteCriteriaDamage/isContractSpEffectLife`，而不是不断过期重建。

独立叠层共用一种外观时，通常只保持一个中性视觉效果。原生长效与自定义短效共用隐身等状态/VFX 时，仅管理自己的 ID，并检查是否已有其他来源，避免缩短或移除原功能。

联机视觉与本机机制分别检查。远端效果链可能有同 ID 多个副本，有效效果查询未必暴露所有显示节点。旧结晶外壳方案在查看者端修剪副本，但原生移除函数还会调整效果状态计数，不能把它视为纯UI清理。0.17.10已移除该逻辑，改为拥有者使用原生同ID刷新与短期显示寿命；没有替队友重授实际机制。类别10的堆叠与类别20的同ID复用，以及复活后补发的证据和边界见 [效果栏同步](effect-sync.md)。变身等免受击状态仍需同步视觉资格，短时长续期的VFX连续性需实测。
