# MMV 鸦人骑士骨骼越界（2026-11-10）

MMV 群友版 0.17.304 赶路时发生访问冲突。Windows 转储记录异常 0xC0000005，故障位于游戏 RVA 0x1949A2F，骨骼父链构建写入空缓冲区。54 层异常线程调用地址与 2026-11-09 的赶路崩溃一致，包含 hkbTwistModifier 激活；没有 NRHex 调用帧，不能据此排除所有更早的内存破坏。

## 角色与资产核对

- 动作上下文：`c4690_9006[m46_69_27_50]`。
- 当前 MMV 地图 m46_69_00_00 将此实例映射到 c6210，NPC 62100020、Think 62100010、Entity 46690840；目录标注为爪型鸦人骑士。
- c6210 的骨架有 115 根骨骼，有效编号 0～114，静态父链无越界和环。
- 行为成员 7000500 中，Fall_Twist_Neck 的起止索引均为 124，Fall_Twist_Head 均为 130，全部越界。
- 实际 Neck=72、Head=73。节点变量绑定没有骨骼索引字段；保持既有绑定。
- 当前修复层只覆盖 c6220，未覆盖 c6210。两次崩溃的敌人不同，不能把本次判为 c6220 修复加载失败。

## 修复与验证边界

新增 `compat/mmv-fixes/c6210-twist-bones.json`，对原行为包、动画包及两个内部成员进行 SHA256 校验后，只替换四个 16 位索引。MmvFixes 构建器同时构建 c6210 和 c6220 修复，逐成员检查无关内容、压缩包回读以及原输入未改动。继续使用独立 MMV-Fixes 文件包，原 MMV 资源不改。

转储没有保留实际 modifier 与 skeleton 堆对象，故不能恢复具体激活节点或解释栈中的 124/130 组合。静态错误与运行时路径高度吻合，但修复效果仍需在游戏内验证。先前 c6220 修复后崩溃的运行时索引差异尚未解释，不应宣称所有赶路崩溃均已解决。
