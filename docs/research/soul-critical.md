# 灵魂暴击

版本0.17.302。文案：**处决时，引发冲击波**。使用攻击类海克斯图标；进入普通抽取和惊喜盲盒，无角色限制。独立版与MMV分别生成处决主段识别表。

## 行为与数值

本机持有者对处决目标造成有效处决伤害时，累计本次处决的折后伤害。前导特效已按用户要求关闭；主段有效命中时锁定伤害和位置，并在该通知内直接生成一次冲击波，基础伤害为`400 + 0.25 × D`，D包含主段及此前已结算的处决段。没有时间冷却；处决中断或结束后清空本次累计，下次处决重新开始。读取命中记录的最终HP伤害值，不用实际HP差，因此致死溢出部分不被剩余血量截断。

冲击波按原生候选的250物理／150魔力比例分成62.5%物理、37.5%魔力，再接受各目标本次防御、减伤和格挡。冲击波属于词条攻击，清除处决分类；来源增伤不再次乘入这个固定伤害快照。原处决已经获得的处决增益保留在D中。侵蚀按词条来源处理。

按目标脚下位置到本次冲击波中心的三维距离选择冲击力：4米内（含4米）为7号，外圈为5号。保留10点基础削韧、30点基础救援值；击退距离参数1.2米，不随距离变化。冲击力是受击动作分类，不是削韧数值；是否实际位移仍受目标动作、强韧与碰撞约束。以原生范围弹丸碰撞方向产生向外的受击方向，未添加强制移动代码。

冲击波生成在被处决目标的脚下，半径在0.1秒内从0.1米扩至10米，存活0.2秒。沿用原生候选的穿透地形／不检查中心射线设置；不同楼层的实际表现需实机确认。同一冲击波对同一角色只命中一次。自0.17.299起，仅原处决目标在该波接触期间绕过3DF380这一层无敌查询；不代表绕过全部处决保护。2026-11-09用户反馈原处决NPC仍未受到冲击波伤害，后续调查见下节。

原处决目标的完整64位句柄和伤害一起记录在Wave／Discharge，不依赖当前处决状态或全局“最后目标”。现有四浮点系数通道中第一项仍保存伤害，其余三项按22／22／20位分段保存目标，末段加独立标记；各段均为可精确表示的有限整数。34058E本地拷贝与33E1A3网络系数拷贝保留这四项，工厂读取后仍恢复四个中性系数。旧版无标记快照、无效句柄和引雷弹丸不会获得绕过资格。

33C120接触期间用可嵌套线程局部作用域限定目标和本次命中；嵌套普通攻击也会遮蔽外层例外。仅目标句柄匹配、冲击波弹丸95005250且命中与原生参数引用均为AtkParam_Pc 95005260时，新增签名校验入口3DF380返回非无敌；原生436370后续拒绝条件与关系查询继续执行。不修改角色标志、攻击参数或虚表；作用域退出自动恢复，已有单目标去重保持不变。

## 主段与生命周期

生成器从目标版本的`EquipParamWeapon`普通／英雄动作组出发，解析`c0000.anibnd.dcx`中的TAE继承，读取31700～31760处决动画的304事件，并沿BehaviorParam_PC、Bullet查到`throwFlag=2`的AtkParam_Pc。以五属性攻击补正与固定基值的合计排名选主段，相等时选较晚事件；该排名仅用于确定动画段，D仍取运行时折后伤害。输出按攻击ID与当前处决动画排序，遇到不同武器组对同一键给出冲突结论则构建失败，不在运行时猜测。

MMV存在重复参数编号：只对实际引用的关键行要求数据一致，忽略行名差异，冲突则失败；不因无关重复编号丢弃整个表。排除原生技艺辅助装备的占位动作组合，保留MMV实际武器及执刑者英雄动作。独立版382条映射，MMV460条。

运行时通过已有且有签名校验的原生当前投技动画入口`490890 → 4932C0`读取有效投技状态，记录持有者、首个处决目标、动画和ChrThrowMan。原生阶段0返回-1，逐帧更新据此结束本次处决；同对象／同目标的新处决不会继承已消费状态。其他目标的通知不重开本次处决。结算通知采用一次43D260分派内的去重标记，不以同帧或固定秒数去重。

## 2026-11-09：原生处决伤害路径调查

本节是当前EXE静态控制流和隔离函数执行的结果，不是新的玩法补丁。EXE SHA256为`9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`，地址均为RVA。未写运行中游戏、未更新DLL或资源。

### 动画事件与指定目标

1. `414820`动作事件分派在`414869`比较事件类型`0x130`（304），跳到`4150E2`。读取事件参数+4的行为判定编号，通过角色虚表+328解析实际行为；`415158`将行为编号、挂点及来源槽信息传给伤害模块的`42FED0`。
2. `42FED0 → 490840 → 4FCB40`从当前ChrThrowMan取得受方句柄，再通过`518F30`解析角色。这是处决配对对象，不是镜头锁定对象，也不需要刀刃碰撞重新找到目标。
3. `430079 → 538FC0`构造原生攻击。`E6FCB0`读取行为，`6D17B0 / E70030`构造攻击数据，`538470`创建攻击实例。`53915E → 531D90`为实例添加指定目标记录：实例+1E0指向包含位置偏移与目标完整句柄的记录，+198置位4。
4. `535260`存在明确的指定目标分支：+1E0非空时解析保存的目标，计算目标位置加偏移，直接调用`5363A0`提交该对象，不走下方普通空间搜索分支。之后仍保留命中记录、来源类型分派及相应资格检查；不能把“指定目标”理解为忽略所有保护。
5. 角色来源经`52CEF0 → 43ED80`，弹体来源经`52CEF0 → 33C120`；两者最终可进入目标伤害模块。原生`436530`会进一步决定是否调用`438610`和`43D260`，后者是现有灵魂暴击读取最终伤害通知的位置。

原生处决的时机和段数来自TAE事件，伤害行来自武器行为映射，因此不同武器可以有不同倍率和多段伤害。不能把所有处决简化为统一固定伤害或唯一倍率。`throwDamageAttribute`的参数定义也明确：只有`throwFlag=2`时，其对应的特殊效果分类才生效。

### 无敌查询之后仍有“仅接受投技伤害”的门控

原生AtkParam的`throwFlag`位于+7D。`E70700`读取它，`E70704`写入运行时命中记录+121。`436530`中的关键分支：

```text
目标行为模块+58的bit3未置位：继续其他投技状态及普通伤害处理
bit3置位：
    命中记录+121 == 2：进入438610及43D260
    命中记录+121 != 2：跳过上述两个调用
```

该门控位于`436370 → vtable+200 → 3D3DB0 / 3DF380`的普通无敌查询之后。当前私有攻击95005260在参数生成时明确设置`throwFlag=0`。因此当前补丁即使让3DF380返回“非无敌”，也不能使这类命中通过上述投技伤害门控。

`tools/verify_native_critical_gate.py`在独立进程的EXE副本内执行真实`436530`，对照目标标志0／8与命中投技标记0／1／2，共6种组合：无该保护时三者均到达伤害出口；有该保护时只有2到达。反应／伤害出口、角色服务、联网后处理及命中复制等为夹具。结果保存到`work/soul-critical/native-gate/validation.json`。这证明了遗漏的原生分支；尚未采样用户失败那一击，不能断言它是实机唯一阻拦点，也不能把到达出口等同于验证最终扣血。
