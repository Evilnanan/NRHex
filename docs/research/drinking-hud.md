# 豪饮的原生HUD图标与计数

2026-10-09，代码0.17.15。EXE 1.3.3.0，SHA256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`；原生参数内部版本10350000。

原有豪饮80个独立效果为95000501及95005001～95005079，寿命15秒、各层AttackRate 1.05。原来iconId=21206是物品奖励的大图标，不是HUD使用的status图集。本次改为原生临时攻击力增益20006，用当前SpEffectParam 1681的iconId验证；单一中性红光95000509仍无图标。所有其他效果字段及其他参数表不变。

当前版本原生路径如下（均为RVA）：

| 路径 | 已核对的作用 |
| --- | --- |
| 7DB180 → 50A890 | 本人HUD从当前效果管理器汇总；7DA8B0也从队友当前角色汇总 |
| 50A890 → 511A00 | 遍历效果节点，过滤失效实例，检查图标和时长资格 |
| EA0BB0 | 读取主／次等四个图标字段，每个非负图标送入20字节条目 |
| 511A00 → 7DEB30 | 条目包含效果ID、图标ID、图标序号、剩余时长、数量1；普通分支按图标合并并累加数量，取较长剩余时长对应条目 |
| 7C913E → 7CFE40 | 将本人汇总向量转为HUD图标数据；20字节条目+10的数量拷贝到图标数据+40 |

`dispDartDebuffStacks` 位于SpEffect参数+3C5的bit6。7DEB30的该分支按效果ID向下取整到百位分组，显示ID%100的最大值，属于追踪者毒箭那种等级编码，不适用于豪饮的可循环独立槽位，保持0。普通分支已能统计生效实例，无须DLL伪造数字、周期补发显示效果或新增hook。

计数沿用原生按图标合并的规则。其他来源也使用20006时会共同计入该图标的数字，不能把它解释为任何情况下都只统计豪饮。不同图标的效果不混入该计数。层数依赖当前原生有效节点，独立到期、槽位复用和角色清理不需要另加显示状态机；原有豪饮状态机继续管理实际伤害。

验证：`tools/record_drinking_hud.py` 将7DEB30原始机器码复制到本机隔离内存，对预分配的人工条目执行普通聚合路径，覆盖0／1／2／3／7／15／40／80层、到期后2→1、槽位复用1→2、全结束以及不同图标分离。没有启动游戏、执行实际UI渲染或网络同步。增量参数构建回读逐行逐字段比较，只允许80个iconId变化；成品报告 `dist/drinking-hud-validation.json` 明确实际游戏和联机尚未验证。

后续可用Ctrl+F6随机奖励领取豪饮（0.17.22已移除旧的豪饮测试组合），连续喝瓶观察一个图标和数字；间隔喝瓶观察分层到期递减，最后一层结束后消失。若还有原生20006增益，其数字会按原生规则合并。
