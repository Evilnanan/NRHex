# 救护车（0.17.167）

95003400：朝濒死队友方向冲刺、疾跑、奔跑免精力；施加救援时按实际救援槽减少量的50%回复自己的精力。方向容差左右各30°，不加距离上限。难度修正人数大于1时才能进入候选，人数未初始化时暂不提供；已获得的能力不因人数变化移除。

## 移动

原生100300（0.115秒间隔）与102022（0.075秒间隔）均每次消耗1点精力。核对原始九套角色TAE的66／67事件：前者出现在20200～20230、23200～23250及疾跑跳衔接，后者出现在20300～20330及相应跳跃衔接。100320虽同为每0.1秒消耗1点，但没有发现相同的移动TAE引用，不作免除。

5085A0汇总所有本轮有效效果的精力变化。拥有者满足方向条件时，按原函数的节点资格位、字段位置和f32加法顺序汇总，仅跳过100300／102022；其他周期消耗和恢复保留，不写PARAM或效果节点。没有通用consumeStaminaRate=0，也没有事后把精力补满。普通攻击、法术、格挡和翻滚等自身的精力结算入口保持原样；疾跑跳本身的起跳费用也保持原样。

HKS Update通过私有env(990034, MoveAngle, MoveSpeedLevel)报告角色的移动输入，SprintStart在调用原AddStamina前再查询一次。满足条件时仅把这次起步费用参数替换成0，仍执行原AddStamina及其停止自然回精力的指令。查询使用原生D40560读取数值参数，其他env请求直接转发3F7B50。移动角结合原生角色旋转（3CEB20）转为水平移动方向，镜头不参与比较。静止／非法输入、超过一帧未更新、对象代际变化均不沿用旧样本。

队友来自WorldChrMan的5197E0玩家登记表，排除自己。Player+710必须为1（濒死），复苏过渡2不算目标；坐标未准备时不启用免耗。

## 救援及原生通知

66DEC0读取命中+150的救援值，经原生倒地档位及+258救援补正，扣减Player+714救援槽并下限截到0；成功救援时调用3D7610(source, recipient)。在这个结算范围捕获前值，通过该原生成功通知读取后值；仅本机存活拥有者作为source时计入，单次通知范围只消费一次。

队友拥有其角色的救援结算权限，不能只依靠本机66DEC0。原生29号通知携带救援后的槽值及救援者身份，4F37D0接收分支3更新远端槽、解析原救援者，再调用相同的3D7610。本实现同步包裹原接收过程，支持519750及519140两种目标身份解析格式，不自建网络协议、不发送额外通知。重复快照的槽差为0；非救援分支及其他来源不回复精力。

回复量为正的实际槽差×0.5，保留不足1点的余数，调用4261D0／427F00原生加精力与上限处理。满精力不储存溢出，下次角色代际或失去能力时清空余数。过量救援只计算槽实际减少的部分，不根据HP伤害、攻击判定次数或救援动画猜测。

通知携带的是槽快照，真实联机中还需要验收延迟、多名救援者交错和原生救援槽回退的时序，隔离测试不能证明这些情况的精确效果。
