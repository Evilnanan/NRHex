# 救护车（0.17.169）

95003400：朝濒死队友方向冲刺、疾跑、奔跑免精力；本人对所有队友输出的救援共用进度，按目标档位折算，每累计一格回复40精力；包含最后一击超出剩余救援槽的部分。方向容差左右各30°，不加距离上限。难度修正人数大于1时才能进入候选，人数未初始化时暂不提供；已获得的能力不因人数变化移除。

## 移动

原生100300（0.115秒间隔）与102022（0.075秒间隔）均每次消耗1点精力。核对原始九套角色TAE的66／67事件：前者出现在20200～20230、23200～23250及疾跑跳衔接，后者出现在20300～20330及相应跳跃衔接。100320虽同为每0.1秒消耗1点，但没有发现相同的移动TAE引用，不作免除。

5085A0汇总所有本轮有效效果的精力变化。拥有者满足方向条件时，按原函数的节点资格位、字段位置和f32加法顺序汇总，仅跳过100300／102022；其他周期消耗和恢复保留，不写PARAM或效果节点。没有通用consumeStaminaRate=0，也没有事后把精力补满。普通攻击、法术、格挡和翻滚等自身的精力结算入口保持原样；疾跑跳本身的起跳费用也保持原样。

HKS Update通过私有env(990034, MoveAngle, MoveSpeedLevel)报告角色的移动输入，SprintStart在调用原AddStamina前再查询一次。满足条件时仅把这次起步费用参数替换成0，仍执行原AddStamina及其停止自然回精力的指令。查询使用原生D40560读取数值参数，其他env请求直接转发3F7B50。移动角结合原生角色旋转（3CEB20）转为水平移动方向，镜头不参与比较。静止／非法输入、超过一帧未更新、对象代际变化均不沿用旧样本。

队友来自WorldChrMan的5197E0玩家登记表，排除自己。Player+710必须为1（濒死），复苏过渡2不算目标；坐标未准备时不启用免耗。

## 本机输出救援

0.17.168移除66DEC0、4F37D0、3D7610的回精hook和TLS槽差快照。新入口43DA77位于43D260的实际命中流程，接触／防御处理之后、玩家类型和3D3FE0接收者权限检查之前。R14为伤害模块，R12为已解析的角色来源，RSI为命中描述符；中途hook保存flags、易失整数及XMM寄存器，重定位原指令后继续原流程。439E80还被预计算调用，不能在其通用回调里直接发放精力。

仅来源为本机存活拥有者、目标是登记队友且Player+710为1时，读取命中+150和+258。按66DEC0同样的f32顺序计算：原始救援值×可选倒地档位修正，再乘命中救援补正，截断为整数；修正前截断值至少1时，最终值最低为1。复用6AEB20模式查询和E76D50的GameSystemCommonParam读取；档位1／2／3以上分别用+40C／+410／+414，否则倍率1。签名完整覆盖原生这段计算，异常非有限或越界输入不奖励。

0.17.169按原生GameSystemCommonParam的+380／+384／+388读取整槽长度40／90／240，除以当前倒地档位1／2／3，得到每格40／45／80点救援值。所有目标共享一份进度，命中时按该目标档位折算，不因切换队友或档位清空；20点一档输出加40点三档输出恰好为一格。内部每格720单位，使三档整数救援值分别按18／16／9转换，避免反复输出1点时的浮点换算误差。满一格消耗720单位并调用4261D0／427F00原生加精力40点；一次命中可兑现多格，仅保留不足一格部分。

连续5秒未输出正救援时，共享进度每秒衰减30点标准进度；标准一格40点，即每秒0.75格或540内部单位。倒地档位只影响新输出的折算，不改变已累计进度和衰减速度。使用原生Update的游戏dt，跨越5秒的那一帧只扣除超出部分，dt=0不推进；新的正输出重置5秒计时，零输出、同步通知和其他人的救援均不刷新。最低为0，不产生负债。普通菜单未暂停游戏模拟时仍推进，不能用菜单是否打开代替dt。

不读取Player+714，不截断到剩余救援槽，不等待66DEC0在队友权威端执行或29号包返回。目标已进入复苏过渡或正常状态不产生新进度；既有未满格部分继续按共享计时衰减。只在原生实际命中到达43DA77时计入，预计算、原生救援应用及同步通知不会重复计入。原生救援槽、回退速度、结算权限、归属和网络通知保持原样。

精力上限只限制实际回复，完整格数在满精力时照常消费，不储存待回复精力；未满格进度按上述计时保留。本人角色代际变化、倒地／死亡或失去能力时清空临时进度，与原有本机拥有者状态边界一致。
