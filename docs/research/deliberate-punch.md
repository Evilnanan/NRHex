# 蓄意轰拳：实现调查（2026-10-28）

当前版本0.17.258，英文名Haymaker，拥有者编号95004800，历史位45。仅无赖可抽到；本次强化技艺期间分别累计承受的折前、折后伤害，结算时取两个累计总量中的较大者，每22点换取1%反击增伤，计入量不超过起手最大HP的3.5倍，与回归基本功加算。

## 双路累计与玻璃大炮联动

设本次有效受击的折前总量为 `sumBefore`，折后总量为 `sumAfter`，最大HP为 `H`：

```text
计入量 = min(max(sumBefore, sumAfter), 3.5 * H)
轰拳增伤比例 = 计入量 / 2200
与基本功合并后的倍率 = 1 + basicsBonus + 计入量 / 2200
```

两路按同一组有效受击分别累加，最后比较总量；不逐次取较大值再相加，也不把两路相加。比如两击的（折前，折后）分别为（100，25）和（100，250），最终比较200与275，计入275，而不是350。

折后量包含原生减伤、易伤和玻璃大炮的承伤倍率，以及适用的自定义承伤修正，但必须在不死下限、剩余HP等扣血限制之前取值，不能使用实际HP差。命中仍需通过有效性判定，不因锁血后实际损失为0而排除，也不凭保留的正伤害元数据计入被无效化的命中。

现有构建代码将玻璃大炮八种DamageCutRate设为10。仅考虑它与704000的0.25承伤系数时，组合为2.5倍；例如折前600会对应折后1500，本能力取1500并提供约68.18%增伤。此例忽略其他防御／减伤及取整，不表示所有实战命中都是2.5倍。

联动由实际伤害数值自然形成，无需在本能力里额外检查玻璃大炮拥有者、再乘10或授予专属倍率。作为隐藏联动保留在机制说明，展示文案无需点名玻璃大炮。两路应成对提交和锁定，避免只记录其中一路或在缓存重放时重复增加。

原版无赖15级、无额外生命加成时H=1200，计入上限4200，轰拳最多约+190.91%；搭配基本功+150%时为约4.4091倍。H在本次技艺起手时采样；中途最大HP变化不回改本次上限。

## 锁血与伤害是两层

SpEffect 704000 的八种物理／元素 DamageCutRate 均为0.25，同时提供 stateInfo143。704001 是另一个阶段标记；二者不能互相替代。

普通命中路径在439E80计算伤害并写入命中描述符+280。43BFB1读取这个伤害，取负后在43BFDE调用426130；后者把变化量加到当前HP，再调用427BC0。

427BC0在目标HP小于等于0时查询状态143（427C92～427CA9），存在时在427CFA将提交HP改为1。此处不重写命中描述符中的伤害。因此不死保护不意味着伤害元数据必然为0；HP差值会被残余血量截断，而+280又已经包含减伤，二者均不能直接代替设计要求的折前量。

隔离执行实际427BC0机器码，覆盖有／无状态143及非致死、刚好致死、过量、1HP承伤共8例。所有权／效果查询与最终HP写入使用明确的桩；验证的是原生下限分支，不代表完整受击已在游戏中验证。

6C5FC0是现有项目已接入的伤害合成函数，接收五属性攻击、攻击修正和独立的防御／减伤系数数组。隔离执行该函数及其原生小于1舍入辅助函数，验证0.25、0.125和0三组承伤系数下，正常结果与使用独立中性系数计算的参考结果；原输入保持不变。可考虑只读旁路计算折前量，不必临时删减伤效果或解除不死。

原生439E80在合成之前还有条件性的506700对象防御、HP型输入和攻击者物理追加处理。因此实现除中和6C5FC0承伤参数，还观察对象防御差额及其后续缩放；进攻侧补正保留，不能把五属性输入直接相加，也不使用最终整数伤害除以0.25反推。

## 强化就绪会在进入强化反击时被消费

原始 HKS函数605 `SmashAttackStanceStart_onUpdate` 的原生转入分支：

1. 满足原生转入条件后查询704011。
2. 持有时提交 `act(2002,704010)`，把 `POWER_DAMAGE_COUNTER` 置0，进入 `W_SmashAttack2`。
3. 不持有时进入 `W_SmashAttack1`。

704010和704011均为spCategory201、categoryPriority60，与项目已核对的同类别替换机制一致。二者还具有状态2252调用条件。原生效果提交可能延迟，因此不能要求同帧查询立即变化。

已用最小解释器执行原字节码中这段分支，验证转入条件成立／不成立与有／无704011的4种组合。不是重写玩法公式。强化资格必须在原生选中强化分支时锁存；仅在后续受击时检查704011会漏掉已消费资格的强化动作。704000同时覆盖普通和强化技艺，也不能单独作为强化资格。

## 原生计数器不是伤害总量

ExecDamage中 `POWER_DAMAGE_COUNTER` 按 DAMAGE_LEVEL 分支增加固定值：NONE为3、MINIMUM为5、SMALL为15、MIDDLE/PUSH为20、LARGE为25，多个更重等级为30。达到原生阈值后申请704011。该段代码未按本次HP伤害累加。

它用于原生强化准备，不能用于本设计的“每22点计入伤害”换算；新能力需要独立保存本次折前／折后两路累计，不改写这个原生计数器。

## 受击标记、防护与出拳的窗口不同

原始 `a904.tae` 的541020片段：

| 事件 | 原始时间轴（秒） |
| --- | --- |
| 103020受击反应标记 | 0～0.9 |
| 704001阶段标记 | 0～0.9 |
| 704000减伤／不死保护 | 0～3.0 |
| 攻击行为6210、6250 | 约1.8667～2.0333 |

HKS ExecDamage实际查询103020以进入无赖技艺受击动作分支。时间为原始TAE时间，不保证实机墙钟时间，也不是新能力应硬编码的定时器。完整事件已读取，时间与关联参数经过断言。

不能在103020／704001消失时删除累计值，也不能把0.9秒直接宣布为设计中的完整累计窗口。需要按强化动作身份跟踪本次施放，在规定的反击产生边界锁定倍率，并让本次命中的多个目标共用；后摇受击不能回改已经结算的反击。动作取消、死亡、失去能力与新局须清理临时累计。

## 收窄攻击白名单

现有 basics.rs 的无赖白名单包含整个技艺系列：600000200、210、220、230、231、240、250。

实际参数与行名显示：200是普通拳，210是强化拳，220是起手踩地；230／231是另两条有伤害的拳击变体，分别由Bullet 30904110／30904111引用（寿命均0.05秒）；240／250是施加7500401降攻效果的辅助命中，基础伤害及属性攻击补正为0。

实现只允许PC攻击表中的600000210和600000231，且必须已收到本次原生W_SmashAttack2分支通知。排除起手踩地、普通拳和纯附加效果命中，保留原生遗物效果。原生Bullet 30904010／30904020分别引用普通200／强化210；30904030引用踩地220。弹体命中由原生计算器解析拥有者，不把泛型弹体指针当角色。

## 实现与边界

- `reward_choices::exclusive_role`登记无赖（实际hero=5）。普通抽取和惊喜盲盒共用它，惊喜盲盒不增加额外排除。C#目录追加43项中的新条目，历史仍为六字节；增加惊喜盲盒隐藏选择标记和本地工作实例，圆桌／新局清理拥有效果及标记。
- 只给HKS `ExecEventAllBody`加观察前缀。起手建立本次记录，原生实际进入`W_SmashAttack2`后确认强化资格，普通拳或其他全身动作清理；`ExecEventNoReset`的受击叠加动作不结束记录。普通起手暂存的伤害只有最终选择强化拳才有收益。原生ExecDamage、Smash回调、准备计数器和704010／704011替换保持原样。
- `43D260`实际命中分派建立线程内嵌套作用域。`439E80`计算器只在匹配作用域中保存第一个HP候选，缓存重放不采样，后续防御反弹计算不覆盖首个候选。离开分派即丢弃未提交记录，跨帧不保存命中指针。
- 折前量使用`6C5FC0`原生合成器的独立输出数组，保留攻击分量、攻击补正及进攻侧倍率，中和承伤、防御、防御状态系数。两处输入观察点`43A403`和`43A476`保存物体防御乘法造成的差额并随HP型输入倍率同步缩放，避免除以零；之后的攻击者物理追加量保留。只观察，不改实际输入、参数或HP。
- 在`43BFB1`原生读取本次`hit+280`、调用HP变化之前成对提交，已通过原生无效化与特殊分支。后者是折后伤害，不是HP差；704000仍有效时才计入。每个作用域候选只能取出一次，身份和施放序号必须仍匹配。
- 反击命中上下文构建时锁定增益，弹体路径最迟在首个强化反击结算时锁定，后续目标共用。冻结后的受击不改变本次反击。死亡／倒地、失去能力、身份更换、新局与全身动作取消清理临时值；不改变本局拥有记录。
- `basics::calculated`统一合成`1 + basicsBonus + punchBonus`，单独拥有轰拳也可生效。玻璃大炮联动完全来自折后伤害，不检查该能力拥有状态，不另外乘承伤倍率。
